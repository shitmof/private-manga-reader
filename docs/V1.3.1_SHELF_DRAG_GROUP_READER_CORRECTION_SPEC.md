# 拾画阁：主书架拖动合组与阅读页交互纠偏方案

> 文档性质：V1.4 实施基线与验收规格
> 目标版本：`v1.4.0+5`
> 更新日期：2026-08-31
> 实施状态：已完成自动化、Android 手势与 v1.3.0 覆盖升级验收
> 视觉边界：继续使用当前拾画阁的蓝白、克制、三列书架风格，不做整体换肤

## 0. 这次真正要解决什么

上一版把“书架排序”和“四宫格分组”分别做出来了，但没有把它们连接成用户需要的完整手势，因此只是具备了部分界面和底层数据，并没有达到最终体验。

用户真正需要的是：

1. 主书架本身可以正常上下浏览。
2. 在主书架直接长按任意漫画并拖动，不必先进入另一个割裂的管理页面。
3. 拖动时可以跨屏自动向上或向下滚动，把漫画放到很远的位置。
4. 拖到卡片之间表示改变书架顺序。
5. 拖到另一漫画封面中央并停留，表示准备把两本漫画合成一个书单。
6. 松手后必须询问是否合成，不能直接误合并。
7. 确认后，原来的两本漫画被收进主书架上的一个小框；小框内部以 2×2 四宫格展示最多四本真实封面。
8. 这个书单小框仍然可以在主书架拖动，也可以继续接收更多漫画。
9. 阅读页默认连续、干净、无横线：图片之间不出现黑色缝线，底部也不再出现横跨屏幕的进度滑杆。
10. 长漫画仍然可以通过右侧可抓取的纵向滑轮快速从第一页拖到最后一页。

这不是一次“把顶部下移、底部上移”的版式调整，而是一次主交互模型纠偏。

## 1. 当前实现为什么没有满足要求

以下结论来自 v1.3.0 当前源码，而不是对操作方式的猜测。

| 用户场景 | 当前实现 | 实际缺口 |
|---|---|---|
| 在主书架直接拖动漫画改变位置 | 需要点右上角“整理书架”后才能排序 | 操作入口割裂；普通主界面长按只产生拖动反馈，不完成书与书之间的操作 |
| 一本漫画拖到另一本漫画上 | 整理模式的所有卡片只调用 `onReorder` | 漫画卡不是“合组目标”，只会换位，不会询问合成书单 |
| 漫画拖入已有书单 | 只有现成分组在非整理模式下是 `DragTarget` | 只能“拖入已有分组”，不能从两本普通漫画开始创建分组 |
| 拖动到屏幕边缘继续找远处位置 | `GridView` 有普通滚动条，但没有拖动边缘自动滚动控制器 | 长书架无法一边拖卡片一边跨屏移动 |
| 合组后主书架出现小框 | 已有四宫格分组卡 | 卡片组件存在，但缺少从“书碰书”创建它的入口，因此用户看不到完整闭环 |
| 开始阅读后无横线 | 阅读图片默认使用 10dp 间距；底部控制栏仍有整条 `Slider` | 图片之间可能出现黑色横缝，点出控制栏后又出现横向进度线 |
| 使用右侧滑轮快速定位 | 已有右侧纵向定位器 | 视觉和触控仍需重做为唯一快速定位入口，并确保从首屏可一次拖到底 |

对应的当前代码事实：

- `library_screen.dart` 的整理模式只把任意拖放解释为重新排序。
- 普通模式只有文件夹卡片能接收漫画，漫画卡片不能接收漫画。
- 主书架没有拖动时的顶部/底部边缘自动滚动。
- `reader_screen.dart` 使用 `imageGap` 生成图片间距，默认值为 10。
- `reader_screen.dart` 的 `_ReaderBottomBar` 仍包含横向 `Slider`。

因此，v1.3.0 文档中“主书架拖动整理已完成”的表述，只能理解为底层排序能力已存在，不能理解为本文件定义的最终交互已经完成。

## 2. 术语统一

当前产品里同时存在“文件夹分组”和“书单”，用户看到的是两个相近概念，容易混淆。

本方案采用以下用户语言：

### 2.1 主书架书单

- 用户口中的“把两本书合成一个书单”。
- 占用主书架的一个三列格位。
- 视觉是带外框的 2×2 四宫格小书架。
- 漫画被移动到这个书单内部，在主书架根层不再单独占格。
- 当前内部可以继续使用 `ShelfFolder` 数据结构，但界面统一称为“书单”。

### 2.2 收藏清单

- 当前 `ReadingList` 的非占有式集合能力。
- 一本漫画可以同时加入多个收藏清单，不改变其主书架位置。
- 为避免和主书架书单混淆，界面建议改称“收藏清单”。
- 本轮拖动合组不操作收藏清单。

用户在主书架拖动时看到的提示统一使用：

```text
合成书单
```

而不是“创建文件夹”“加入收藏清单”等内部术语。

## 3. 最终主书架形态

### 3.1 静止状态

主书架继续保持三列，不更换当前整体 UI 风格：

```text
┌──────────────────────────────┐
│ 拾画阁                搜索  选择 │
│ 全部  最近  置顶  书单  私密    │
│                              │
│ [漫画A]   [漫画B]   [书单一]   │
│  标题      标题      4本       │
│                              │
│ [漫画C]   [漫画D]   [漫画E]   │
│  标题      标题      标题      │
│                              │
│ [漫画F]   [书单二]   [漫画G]   │
│                              │
└──────────────────────────────┘
```

- 漫画和书单使用同一套三列网格和同一套顺序。
- 整页可以像普通手机文件列表一样上下滑动。
- 快速滚动条只在滚动时短暂出现，不遮挡右上菜单。
- 书单必须直接出现在主书架，而不是只存在于“移动到分组”弹窗。

### 3.2 书单小框

```text
┌──────────────┐
│ ┌────┐┌────┐ │
│ │封面││封面│ │
│ └────┘└────┘ │
│ ┌────┐┌────┐ │
│ │封面││封面│ │
│ └────┘└────┘ │
└──────────────┘
想看的漫画       ⋯
共 12 本
```

规格：

- 外框与漫画封面区宽度相同，不变成横跨整行的大卡片。
- 内部固定四格；不足四本时保留空白格，不拉伸已有封面。
- 超过四本只显示前四本，下面显示“共 N 本”。
- 私密书单使用中性占位封面和锁图标，不在锁定状态泄露真实内容。
- 点击进入书单内部；返回手势先回主书架，不退出 App。
- 长按书单小框可以整体拖动改变位置。
- 将漫画拖到书单中央可以加入；从书单内拖出可以移回主书架。

## 4. 直接拖动与重新排序

### 4.1 启动方式

- 在主书架长按漫画 300～450ms，漫画轻微抬升并产生一次轻触震动。
- 长按后立即进入本次临时整理状态，不要求用户先点右上角“整理书架”。
- 手指不松开即可直接拖动。
- 原位置显示同尺寸半透明占位框，其他卡片实时让位。
- 松手后保存新顺序，并退出本次临时整理状态。
- 右上角仍可保留“整理”按钮，作为批量或无障碍入口，但不能成为拖动的唯一入口。

### 4.2 卡片之间：改变顺序

每张卡片周围设置插入区：

```text
┌─────────────────┐
│ 上方 25%：插到前面 │
│                 │
│ 中间 50%：合成书单 │
│                 │
│ 下方 25%：插到后面 │
└─────────────────┘
```

三列网格实际还要结合左右方向计算最近插入索引，但用户只需要看到一条清楚的蓝色插入标记。

- 拖到卡片边缘：只换位置，不弹窗。
- 其他卡片实时移动，显示最终落点。
- 拖动漫画、书单都使用同一套排序规则。
- 保存后重启 App，顺序必须保持不变。

### 4.3 跨屏拖动：边缘自动滚动

拖动状态下，屏幕顶部和底部各设置约 64dp 的隐形自动滚动区：

- 拖到顶部区域：书架持续向上滚动。
- 拖到底部区域：书架持续向下滚动。
- 越靠近边缘，滚动速度越快。
- 离开边缘区域立即停止自动滚动。
- 到达书架首尾后停止，不产生抖动。
- 拖动过程中卡片始终跟随手指，不能被系统滚动手势抢走。

该能力必须能处理至少 600 个书架节点，而不是只验证首屏九本漫画。

## 5. 漫画拖到漫画：询问合成书单

### 5.1 识别合组意图

当漫画 A 被拖到漫画 B 的封面中央时：

1. B 的边框变为蓝色，缩放到约 0.94。
2. 中央浮现“四宫格/书单”提示图标。
3. 停留约 600ms 后产生第二次轻触震动，表示已进入合组候选状态。
4. 手指在候选状态下松开，才弹出确认；快速掠过不会创建书单。

### 5.2 确认弹层

```text
┌──────────────────────────┐
│ 合成书单                  │
│                          │
│ [封面A]  ＋  [封面B]      │
│                          │
│ 书单名称                  │
│ [ 新建书单              ] │
│                          │
│        取消     合成       │
└──────────────────────────┘
```

规则：

- 标题必须明确询问“是否合成书单”。
- 默认名称为“新建书单”，输入框自动选中文字，用户可直接改名。
- 点“取消”或下滑关闭后，A、B 的位置与归属完全不变。
- 点“合成”后才执行数据库事务。
- 不能先移动再询问，避免取消后顺序错乱。
- 同名书单允许创建，但可以在名称下方轻提示“已有同名书单”。

### 5.3 确认后的结果

- 在 B 原来的位置生成一个书单小框。
- A 和 B 从主书架根层消失，进入该书单。
- 四宫格前两格显示 A、B 的真实封面，后两格为空。
- 新书单计数为“共 2 本”。
- 其余卡片自动补位，不打乱未参与操作的相对顺序。
- 数据写入必须是单事务：创建书单、移动两本漫画、更新主书架节点顺序要么全部成功，要么全部不发生。

### 5.4 后续拖动

| 拖动对象 | 放置目标 | 最终行为 |
|---|---|---|
| 漫画 | 另一漫画中央 | 询问合成新书单 |
| 漫画 | 已有书单中央 | 询问“加入《书单名》？”后加入 |
| 漫画 | 卡片间隙 | 只改变主书架位置 |
| 书单 | 卡片间隙 | 改变整个书单位置 |
| 书单 | 漫画 | 不允许直接嵌套；显示不可放置反馈 |
| 书单 | 书单 | 本轮不做嵌套或直接合并，防止误操作 |
| 书单内漫画 | 主书架空位 | 移出书单并插入指定位置 |

书单只剩一本或变空时不自动解散，避免系统替用户做不可预期的删除；由用户在书单菜单中选择“解散书单”。解散只移动漫画，不删除漫画数据。

## 6. 阅读页横线问题

用户所说的“开始阅读后还是有一条横线”，当前实现中可能同时来自两处。为了不再遗漏，本方案两处一起处理。

### 6.1 图片之间的横向黑缝

当前每张图片下方默认保留约 10dp 间距，在深色背景上会表现为明显横线。

最终效果：

- 默认阅读模式改为“无缝连续”，图片上下边缘直接衔接，默认间距为 0dp。
- `v1.3.1` 首次升级时，将旧版本内置默认值 10dp 迁移为 0dp；其他用户主动选择的非默认值保留。
- 阅读设置保留三档：无缝 0dp、窄缝 4dp、舒适 10dp。
- 用户主动选择有间距时，使用中性背景间隔，不绘制额外分割线、阴影或边框。

### 6.2 底部横向进度滑杆

当前点一下阅读页后，底部会出现横跨屏幕的 `Slider`。它与用户要求的右侧纵向滑轮重复，而且遮挡图片、影响观感。

最终效果：

- 删除阅读页底部整条横向 Slider。
- 点按屏幕中央后，只浮现顶部操作栏与底部紧凑页码胶囊，例如 `156 / 628`。
- 页码胶囊不铺满整行，不绘制横线，不推动图片布局。
- 快速定位统一交给右侧纵向滑轮。
- “显示阅读页码”设置只控制页码胶囊，不再控制横向 Slider。

## 7. 右侧纵向快速滑轮

这是长漫画快速定位的唯一主控件。

### 7.1 静止状态

- 阅读时右侧滑轮、轨迹和页码提示完全不可见，不占视觉空间。
- 只有用户触碰右侧隐形热区时才显示滑轮；松手约 1.1 秒后完全淡出。
- 可见部分很细，但实际触控热区至少 44dp，保证容易抓住。
- 滑块约 14×28dp，不能是横跨页面的长线。
- 不遮挡顶部设置、书签和更多菜单。

### 7.2 拖动状态

- 手指按住右侧热区任意位置即可开始定位，不要求精确按中滑块。
- 从轨迹顶部一次拖到底部，必须能从第 1 页直接到最后一页。
- 拖动时左侧显示浮动页码：`156 / 628`。
- 可选增强：页码旁显示当前页小缩略图，但不能因为生成缩略图阻塞拖动。
- 松手后停在目标页，阅读位置立即成为待保存进度。
- 松手 800～1200ms 后滑轮和页码提示自动淡出。

### 7.3 普通阅读滚动

- 用户仍可在图片区域自由上下滑动，惯性滚动不受右侧滑轮影响。
- 双击放大与纵向滚动的手势优先级保持清晰。
- 阅读器控制层必须覆盖在图片上方，显示/隐藏时不能把漫画整体向上或向下挤动。

最终线框：

```text
┌──────────────────────────────┐
│ ‹  漫画标题       书签  设置  ⋯ │  ← 点屏幕后浮现
│                              │
│          漫画图片             │
│                              ▏│
│          漫画图片       156/628│  ← 拖右侧时浮现
│                              ▏│
│          漫画图片             │
│                              │
│             [156 / 628]       │  ← 仅紧凑页码，无横线
└──────────────────────────────┘
```

## 8. 私密书单与数据保护

- 私密漫画拖到普通漫画上时，确认弹层必须提示“新书单将设为私密”。
- 只要合组对象中任意一本是私密漫画，新书单默认私密，不能自动降级为普通。
- 锁定状态不显示私密书单真实封面。
- 合组、加入、移出、重排都只改索引和归属，不移动、不删除、不重编码原图。
- 取消拖动、取消弹层、写入失败都不得改变原书架。
- 升级继续保留现有漫画、阅读进度、书签、封面、备份和挂载授权记录。

## 9. 状态机与实现约束

### 9.1 主书架拖动状态机

```text
静止
→ 长按抬起
→ 拖动中
   ├─ 进入边缘区 → 自动滚动 → 拖动中
   ├─ 进入插入区 → 显示插入位 → 松手保存排序
   ├─ 进入漫画中央 → 合组候选 → 松手弹出确认
   ├─ 进入书单中央 → 加入候选 → 松手弹出确认
   └─ 离开/取消 → 恢复原状态
```

### 9.2 手势仲裁

- 普通短滑：滚动书架。
- 普通短按：打开漫画/书单。
- 长按后移动：拖动卡片。
- 长按但未移动：可进入卡片菜单；阈值需要避免与拖动冲突。
- 拖动过程中禁用卡片点击，松手后至少一个事件周期内不得误打开详情页。

### 9.3 数据层

现有 schema 6 已有 `shelf_entries` 和 `ShelfFolder`，预计不需要再迁移漫画资源结构。需要新增的是一条原子业务命令：

```text
createShelfGroupFromComics(
  sourceComicId,
  targetComicId,
  groupName,
  insertionIndex,
  isPrivate,
)
```

该命令必须在单个数据库事务中完成：

1. 创建书单。
2. 将两本漫画归入书单。
3. 删除两本漫画在根书架的节点。
4. 在目标位置插入书单节点。
5. 保持其余节点相对顺序。

阅读页只改变显示与偏好迁移，不改变漫画原图数据。

## 10. 必须通过的验收场景

### 10.1 主书架排序

- [ ] 不点“整理书架”，直接长按第 1 本漫画即可开始拖动。
- [ ] 将第 1 本拖到首屏第 9 个位置，其他卡片实时让位。
- [ ] 将第 1 本拖到底部边缘，书架自动向下滚动并能放到第 100 个位置。
- [ ] 将底部漫画拖到顶部，自动向上滚动成功。
- [ ] 杀掉并重启 App 后，新顺序保持。
- [ ] 漫画和书单小框都能参与排序。

### 10.2 书碰书合组

- [ ] 漫画 A 拖到漫画 B 边缘时只排序，不弹窗。
- [ ] 漫画 A 拖到漫画 B 中央停留约 600ms，出现明确合组反馈。
- [ ] 松手后出现“合成书单”确认弹层。
- [ ] 点取消后，A、B 的顺序和归属完全不变。
- [ ] 点合成后，B 原位置出现四宫格书单小框，计数为 2 本。
- [ ] 打开书单能看到 A、B，系统返回回到主书架而不是退出 App。
- [ ] 再拖入漫画 C，书单变为 3 本并更新第三格封面。

## 11. 明确不接受的“伪完成”

以下结果不能算完成：

- 只增加一个“整理书架”按钮，但主界面不能直接长按拖动。
- 只能把漫画拖入预先创建的分组，不能书碰书创建书单。
- 漫画拖到漫画上只交换位置，没有合组确认。
- 合组后只在弹窗列表里出现，主书架没有四宫格小框。
- 拖动只能在当前首屏完成，靠近边缘不能自动滚动。
- 只把底部横线移动位置、缩短宽度或换颜色，没有真正移除横向 Slider。
- 只把图片间距从 10dp 改小，但默认阅读仍能看到横缝。
- 右侧只显示滑轮，却无法按住并一次拖到 600 页末尾。
- 只看 Widget 测试通过，没有在 Android 真机/模拟器完成手势闭环。

## 12. 实施顺序建议

本轮文档确认后，下一轮建议严格按以下 LOOP 执行：

1. 先写失败测试：书碰书、取消不改变、合组事务、拖动排序持久化。
2. 完成主书架统一拖动状态与边缘自动滚动。
3. 完成漫画中央合组候选、确认弹层和原子创建书单。
4. 完成书单小框加入、移出、整体排序和私密规则。
5. 删除阅读页底部横向 Slider，默认图片间距迁移到 0。
6. 重做右侧滑轮触控热区、一次拖到底和自动淡出。
7. 执行 Flutter 分析与自动化测试。
8. 使用 v1.3.0 正式 APK 做覆盖升级和 Android 手势实测。
9. 由用户验收屏幕录制或实机操作结果后，再构建并发布新 APK。

任何一步发现偏差，都回到对应失败用例修正，不能用更换版式代替行为实现。

## 13. 一句话定义最终效果

**拾画阁的主书架要像手机桌面整理图标一样：能直接长按、跨屏拖动、实时换位；一本漫画放到另一本漫画中央时先询问，确认后在原位置生成一个装着真实封面的四宫格书单小框。阅读页则默认无图片横缝、无底部横向进度线，只保留可一次拖到 600 页末尾的右侧纵向滑轮。**
