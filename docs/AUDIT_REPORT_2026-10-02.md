## 1. 审核结论

拾画阁已经具备个人漫画阅读器的主要能力：本地无损导入、书架与四宫格分组、图片编辑、连续阅读、阅读记录、备份恢复和只读挂载。最近的改动在导入重试顺序、备份路径校验、空间说明和发布签名约束上有实际进步。

当前待发布的 1.6.3 **尚未达到发布条件**。本轮重新执行全量测试时，83 项测试通过，但新增备份兼容测试文件无法编译；在独立副本中仅修正测试类声明后，又复现了恢复输入流中断造成文件句柄未关闭、临时目录清理失败的问题。此外，原图复用完整性、部分无效图片误报成功、私密文件夹保护继承仍有缺口。

建议先解决数据与隐私问题，再完成阅读交互修复和 APK 验收。UI 的基础风格已经统一，不需要再推翻书架布局；主要应改善状态反馈、主题切换一致性、空间管理和细节可读性。

## 4. 已确认的优点

### 4.1 本地存储的基本结构合理

原图、缩略图、备份、临时文件、网络缓存分开保存；书架、图片顺序、进度和设置放在 SQLite。图片以内容哈希去重，多个漫画可引用同一份原图；新原图复制后有哈希校验。这个结构适合私人资料库，也能避免重复归组导致原图成倍占用空间。

### 4.2 关键书架与编辑功能已经存在

三列书架、白色四宫格分组、长按拖动、边缘自动滚动、拖入分组、分组内返回主书架均有实现及相关测试。编辑器已有单选、多选、删除、拖动、移动到指定页和保存流程。因此，不能再笼统地说“删除或分组完全没做”；下一步应验收具体触发场景。

### 4.3 导入顺序与重试改造方向正确

当前改动使用独立包标识、稳定图片条目 ID 和原始队列位置处理重试。混合包的散图段与内层漫画包保留相对顺序；失败批次回滚，成功批次保留。回归测试核对实际入库图片数量、哈希、顺序和封面，比只检查“识别到了几个包”可靠。

### 4.4 UI 已形成稳定的白蓝风格

颜色、间距、字体层级、卡片圆角与动效时长集中在 `lib/theme.dart`。阅读定位条默认隐藏、触摸后显示、松手后隐藏，并有关闭热区的测试。新本地空间页将原图、备份与缓存的用途说明清楚，大字号布局也能换行。

`frontend-design` 在这部分工作中的作用是统一信息层级、留白和颜色，而不是改变用户已认可的书架结构。

### 4.5 兼容策略与发布保护有进步

数据库继续使用 schema 8，备份继续输出 v4，没有在这轮引入两套新旧模型。备份新增路径与符号链接拒绝、同路径内容冲突检查和 UUID 文件名，减少越界写入、静默引用坏文件和同秒覆盖恢复点的风险。

发布构建将官方证书指纹固定在代码中，避免本地配置换成另一把密钥也能通过自检。该保护仍需在最终 APK 上验证。

### A01：验证文件本身必须先恢复可执行

`PlatformFile` 是 `base` 类型，继承它的 `_LocalPlatformFile` 需要合适的类修饰符。当前没有该声明，所以新增兼容与安全测试根本没有运行。修好声明后必须重跑，不能引用之前测试文件尚未新增失败流用例时的通过记录。

### A02：恢复失败时仍有文件句柄泄漏

复制备份输入流的代码在循环结束后才调用 `output.close()`，没有覆盖读取中途抛错的路径。独立副本触发输入流中断后，临时目录仍在；Windows 又报告文件被占用、无法删除。

应在异常路径可靠关闭输出，保留原始错误；临时清理不能掩盖真正的读取失败。还应覆盖磁盘写满和目标写入失败。Android 上未实测同一异常，不应声称所有设备都会表现为相同锁错误。

### A03：私密判断需要统一继承规则

漫画移入文件夹时，自身 `is_private` 被设为 0，隐私依赖文件夹标记；阅读和导出只看书本标记。无痕模式关闭时，私密文件夹内的漫画不会申请阅读保护，导出也不触发同样的再次验证。

应统一计算“漫画自身私密，或所属文件夹私密”，供阅读、导出、搜索和相关入口共用。进入私密区已有验证，不等于阅读窗口已受截屏保护。当前私密功能属于访问限制，不是原图或备份加密。

### A04：导入成功应包含已有原图完整性

实际复现步骤：导入一张有效 PNG；在测试目录损坏它的已存原图；重新导入原来的有效文件。结果为成功 1 张、失败 0 张、漫画新增引用，但磁盘上仍是损坏内容。

原因是复用资产只检查文件是否存在，存在就丢弃新副本。建议复用前校验长度与哈希；若修复坏文件，应保留稳定资产 ID、图片条目和书签，采用校验后的原子替换并保留可恢复旧副本。至少不能继续无提示地报成功。

### A05：不能把零尺寸图片直接视为成功

256 个零字节命名为 `.png`，缩略图解码返回 `null`；导入实际返回成功 1、失败 0，入库图片尺寸为 0×0。另一方面，4 字节无效 PNG 会抛异常并被拒绝。因此准确结论是“部分无效图片会误报成功”，不是“所有坏 PNG 都会成功”。

修复时要区分真正无效文件与 Dart 缩略图解码器不支持、但 Android 可能能显示的合法 HEIC 等格式。应增加格式验证或平台解码兜底，并向用户报告真实状态。

### A06：内层包失败隔离还少一个阶段

`_extractNestedArchive()` 在逐内包的 `try` 外执行，临时文件也在返回后才登记为待清理。如果读取或写出内包时抛错，异常会扩大到整个外层包，未完成文件还可能残留。

现有损坏内包测试覆盖“能够解出，但不是有效压缩包”，没有覆盖解压输出流中断。应将“解出、打开、扫描”纳入同一包的失败范围，并验证同包内前后健康漫画继续导入。

### A07、A08：阅读 UI 需要修复状态一致性

偏移索引只用宽度和页数判断是否重建，漏了图片间距。600 页由 0 改为 10 dp 时，尾部累计偏移差可接近 5990 dp；这是根据代码计算的上限示例，不是设备测量。应在间距变化时重建索引，并保持当前稳定页。

阅读设置面板背景在打开时固定，内部文字随新的画纸/夜间模式改变。应让背景、文字和控件在同一可重建区域里更新，验证面板不关闭时往返切换两次。

### A09、A10：挂载需要正确失效与按字节管理

物化缓存只按 URI 命名，非空文件存在就复用。应结合尺寸、修改时间或来源版本判断有效性，并提供“重新读取原文件”。只用 URI 不足以表示内容版本。

6 个文件不等于小空间：6 个大包仍可能占多 GB，复制完成再裁剪还会提高峰值。建议增加总字节预算、复制前空间检查、读取中限制与合理裁剪，保持正在读取文件的锁保护。新的手动清理入口是改善，但不能代替自动预算。

### A11：1000 页上限不是已解决的无限导入

已取消单批 100 张限制，但仓库、导入、详情页、编辑器仍一致限制单本 1000 张。超限压缩包可能先导入大量页面，再失败并回滚整批。至少应在开始前显示本次页数、现有页数和剩余容量。

长期方案可提高容量或增加章节分册，但必须连同编辑、阅读索引、导出和备份一起验证，不能只改一个常量。

### A12：文档会把接手者带回旧签名渠道

README 下载说明给出正确官方证书，但构建示例仍给出历史另一渠道指纹；还有一条未提供配置就回退默认密钥的说明，与发布构建缺失配置立即失败相矛盾。应统一 README、交接与发布说明，以实际 APK 证书和提交为依据。

## 6. 大文件、本地数据与兼容的审核判断

### 6.1 4 GB 是磁盘问题与处理峰值问题，需要分别测量

原图本身约 4 GB，保留原画质就仍需保存这些数据。可减少的是重复原图、无用缓存、临时副本和过量备份。

现有备份先复制原图到临时目录，再生成完整 ZIP，完成前同时存在原图、临时副本和备份。若原图接近 4 GB，额外空间可能接近 8 GB，加上旧备份和缓存会更多。恢复也会同时占用输入包、解出原图、安全备份及新复制文件；当前没有完整的空间预检和保留策略。

缩略图生成完整解码单张图片，阅读虽有图片缓存预算，但它不能限制导入解码的峰值。高像素长图、固实 7z/RAR 的解码行为必须另测。**本轮没有测到具体 OOM，不能写成“4 GB 一定崩溃”，也不能写成“4 GB 已验收”。**

建议采用流式备份、明确临时空间估算、按字节缓存预算、后台缩略图处理和备份保留管理。清理原图必须沿用引用关系与回收站机制。

### 6.2 当前没有新旧格式割裂的直接证据

当前数据库和备份格式未变，兼容入口明确保留 v1～v4。这是积极结论，但只证明数据格式方向一致。APK 覆盖升级还依赖包名、证书和递增 `versionCode`。

历史另一密钥签出的版本仍属于独立安装兼容群，不能靠保持 schema 8 自动解决。不要让用户在未保存外部备份时卸载。未来增加章节模型前，还应补未来数据库版本拒绝打开、清晰错误提示与迁移恢复方案；当前未发现专门的 `onDowngrade` 用户处理路径。

### 6.3 数据保留说明应继续明确

同签名正常覆盖升级会保留应用数据。卸载通常会清除应用内原图、数据库和备份；外部公共目录里的完整备份才是重新安装后的恢复来源。备份恢复中的挂载索引不能替代原文件，目录授权或网络凭据可能需要重新配置。

数据库事务能防止数据库被部分替换，但不意味着所有磁盘文件已经形成完整事务。应补恢复写入失败后的残留文件管理，并避免在旧原图损坏、旧库无法完整备份时让用户陷入“无法恢复也无法备份”的死路。

## 7. 功能缺口与 UI 后续建议

| 方面 | 当前缺口 | 建议 |
| --- | --- | --- |
| 章节 | 多包可追加到同一本，但没有稳定章节 ID 和显式图片归属 | 作为后续独立版本设计，兼容旧书、书签与编辑顺序 |
| 中断续导 | 重试队列与已完成包信息主要在内存里 | 记录导入任务、稳定来源标识和已提交批次；进程重启后可解释和恢复 |
| 备份管理 | 可以创建/导出/恢复，缺少最近外部导出状态、校验与保留策略 | 显示备份位置、完成时间与完整性；清理前明确恢复影响 |
| 修复工具 | 已有回收站与无引用清理，缺少坏原图定位和修复入口 | 列出缺失/哈希不一致文件，允许选择有效原文件重新关联 |
| UI 细节 | 阅读面板主题不同步；新存储页深色蓝色小字对比偏低 | 统一主题语义色，并在浅色、深色、大字号截图中检查 |
| 失败反馈 | 有错误列表，但缺少可保存的脱敏任务结果 | 显示实际导入数量、失败来源和重试状态；支持导出诊断文本 |
