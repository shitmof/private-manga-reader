# 私人书架 v1.2 总体设计稿

> 主题：文件夹式分组、三列书架、快速定位、完整图片编辑、私密阅读与网络挂载完善
>
> 状态：v1.2.0 已实施并完成 Android 验收；实际进入 APK 的范围以下方“实施结果”和 `ACCEPTANCE.md` 为准
>
> 日期：2026-08-30
> UI 基线：沿用当前蓝白、克制、内容优先的视觉风格，不进行整体换肤或品牌重做

## 0. 结论先行

这批需求可以放进同一套产品架构，整体难度为 **中高，4/5**，没有不可实现的部分。真正困难的不是把按钮画出来，而是同时保证以下四件事：

1. 书架分组、私密状态、图片顺序、阅读进度等新数据在升级后不丢失。
2. 600～1000 张长漫画仍能快速定位、低内存阅读和精确恢复位置。
3. WebDAV、OPDS、SMB/NAS 的认证、断网、缓存和重新登录状态清晰可靠。
4. 新 APK 必须用原包名、递增版本号和同一签名原位升级，绝不覆盖用户原图和数据库。

本稿建议把产品组织为四层：

```text
私人书架
├── 文件夹 / 分组
│   ├── 漫画
│   │   └── 图片页面
│   └── 漫画
├── 未分组漫画
├── 私密书架
└── 网络书库
    ├── WebDAV
    ├── OPDS / Komga / Kavita
    └── SMB / NAS
```

核心变化是：**书架从两列改成三列；增加文件夹式分组；阅读器增加可拖动的页码定位器；编辑器补齐多选删除、单张/批量移动和精确移动；私密阅读从“本地保存”升级为真正可锁定的私密区域。**

## 1. 本次需求的统一定义

### 1.1 文件夹式书架

- 用户可以新建、重命名、排序和删除书架文件夹。
- 漫画可以通过拖动或多选操作移动到文件夹。
- 文件夹显示名称、漫画数量和最多 4 张缩略封面。
- 删除文件夹只解除分组，不删除里面的漫画。
- 未加入文件夹的漫画统一进入“未分组”。
- “全部漫画、最近阅读、未读、已完成、私密、网络书库”属于系统智能分类，不与用户文件夹混为一谈。

### 1.2 三列书架

- 当前书架源码为两列，每本封面宽度接近半屏，密度偏低。
- 手机竖屏默认改成三列，仍保留当前留白、圆角、蓝色强调色和标题排版。
- 仅调整信息密度，不改变整体 UI 风格。

### 1.3 600～1000 页快速定位

- 阅读器右侧增加浏览器式可拖动滑块。
- 可以把滑块直接拖到顶部、底部或任意位置。
- 拖动时显示“当前页 / 总页数”、百分比和小缩略图。
- 松手后精确跳到目标图片顶部，而不是只按大致像素跳转。
- 普通手指上下自由滑动继续保留，两种操作互不冲突。

### 1.4 完整图片编辑

- 单击选中/取消选中。
- 支持多选、全选、范围选择和批量删除。
- 长按拖动单张图片改变顺序。
- 多选后可把选中图片作为一个连续块移动，并保持块内原顺序。
- 支持输入目标页码进行精确移动，避免在 600 张图片中长距离拖拽。
- 所有修改先进入编辑草稿，只有点“保存”才写入数据库；点“取消”完全不落库。

### 1.5 私密阅读、下载、分享和书单

- 漫画或整个文件夹可以标记为私密。
- 私密书架使用系统生物识别或锁屏凭据解锁。
- 支持把本地漫画导出成 CBZ 到用户选择的本地目录。
- 支持通过 Android 系统分享面板分享导出的文件。
- 网络漫画支持“离线保存”和“导出到本地”，两者语义分开。
- 书单采用多对多关系：一本漫画可加入多个书单；文件夹仍然是书架中的唯一物理位置。

### 1.6 网络存储挂载完善

- 继续支持 WebDAV、OPDS/Komga/Kavita、SMB/NAS。
- 用户看到的是“挂载后直接打开”，实现层允许使用受控缓存。
- 阅读记录、分组、私密状态和离线状态只保存在手机本地。
- 服务器密码不进入普通数据库、日志、备份包或 GitHub。
- 增加连接状态、最后成功时间、最后错误和重新认证入口。

### 2.2 源码与用户手机安装包不一致

截至 2026-08-30，GitHub 最新正式 Release 仍为 `v1.1.0`，对应提交 `f1f3fa2`。编辑器修复位于其后的提交：

```text
d212eb6  编辑器选择、删除、保存和拖动回归测试
```

因此：

> 用户在已安装 v1.1.0 中仍然无法正常选中删除或拖动，不代表最新源码没有修复；它代表“修复尚未被构建并发布成可下载 APK”。

这项问题必须作为第一个发布门槛解决，不能再把“源码完成”写成“用户已经拿到”。

| 缺口 | 影响 | 优先级 |

| 阅读器没有可拖动定位器 | 600 张漫画定位耗时数分钟 | P0 |

| 没有阅读器独立亮度设置 | 夜间阅读控制不足 | P1 |

## 3. 设计原则

### 3.1 UI 冻结原则

保持以下视觉基线不变：

- 蓝白主色与现有深色主题。
- 大量留白、轻边框、低装饰、内容优先。
- 现有圆角和图标语言。
- 不加入渐变背景、玻璃拟态、复杂纹理或新的品牌色。
- 不改变“私人书架”产品名称和总体导航习惯。

允许的变化只有：三列密度、文件夹瓦片、选择态底栏、阅读定位器、阅读设置面板和必要状态标识。

### 3.2 借鉴而非复制

微信读书的成熟做法可以作为信息架构参考，例如：书单、置顶、阅读进度、分类和私密状态。腾讯公开的微信读书书架说明中也能看到 `archive` 书单、`isTop` 置顶、`secret` 私密和进度相关字段。

本产品只借鉴交互模型，不逐像素复制其页面、图标、文案、品牌素材或专有视觉。这样既保持当前 UI，又避免后续形成不一致的“拼贴式界面”。

### 3.3 数据安全优先

- 升级只新增表或可空字段，不重建旧库。
- 原图永不因界面改版而移动、覆盖或重新编码。
- 删除文件夹不等于删除漫画。
- 移除网络挂载不等于删除远端文件。
- 清理缓存不等于清除阅读记录。
- 分享和导出必须由用户明确触发。

### 3.4 大数据量优先

所有书架和编辑页面使用懒加载网格；阅读器只解码视口附近图片。1000 张是当前产品上限，不应成为底层性能极限。

## 4. 信息架构

### 4.1 书架首页

顶部保留“私人书架”，增加一个轻量的范围选择入口：

```text
私人书架                         搜索  管理  +
全部漫画 ▾

[最近阅读] [未读] [已完成] [私密]

[文件夹]     [文件夹]     [漫画]
[漫画]       [漫画]       [漫画]
[漫画]       [漫画]       [漫画]
```

“全部漫画 ▾”可切换：

- 全部漫画
- 未分组
- 最近阅读
- 未读
- 已完成
- 已置顶
- 私密书架
- 本地漫画
- 网络漫画
- 用户创建的文件夹

### 4.2 三种组织对象

| 对象 | 语义 | 成员关系 | 首页表现 |
|---|---|---|---|
| 文件夹/分组 | 手机文件夹式物理归类 | 每本漫画最多属于一个文件夹 | 作为一个网格瓦片 |
| 书单 | 跨分类收藏或分享集合 | 一本漫画可属于多个书单 | 在“书单”管理页展示 |
| 智能分类 | 系统按状态自动计算 | 不写固定成员 | 顶部筛选/快捷入口 |

这一拆分解决两个冲突：拖入文件夹时位置清晰，而“想看”“收藏”“某作者作品”等书单又可以重复收录同一本漫画。

## 5. 书架三列与文件夹设计

### 5.1 三列尺寸

手机竖屏 `320～599dp` 默认三列：

```text
页面左右边距：16dp
列间距：10dp
行间距：18dp
卡片宽度：(屏幕宽度 - 32dp - 20dp) / 3
封面比例：约 0.70～0.72
书名：单行，超出省略
次级信息：页数或阅读进度，单行
```

在 360dp 宽设备上，单卡约 102.7dp；在 411dp 宽设备上，单卡约 119.7dp。平板根据可用宽度自动增加到 4～6 列，但手机始终以三列为视觉基线。

当系统字体放大到严重影响可读性时，可以降为两列，这是无障碍适配，不视为改变 UI。

### 5.2 漫画卡片

卡片信息控制在三层：

1. 封面。
2. 漫画名。
3. 阅读进度，例如 `156 / 628` 或 `未开始`。

文件大小、来源、创建日期等信息移到详情页，不继续挤在三列卡片上。

状态角标最多同时显示一个：

- 锁：私密。
- 云：网络漫画。
- 下载：已离线。
- 图钉：置顶。

如果一本书同时有多个状态，按优先级 `私密 > 离线 > 网络 > 置顶` 显示，其他状态放入详情页，避免封面被图标覆盖。

### 5.3 文件夹瓦片

文件夹占一个普通书架格，内部为 2×2 微型封面拼图：

```text
┌──────────────┐
│  ▣  ▣        │
│  ▣  ▣        │
└──────────────┘
想看的漫画
12 本
```

- 少于 4 本时用当前蓝色柔和占位补齐。
- 私密文件夹不显示真实封面，默认显示锁和纯色占位。
- 长按文件夹可拖动排序。
- 点按进入文件夹详情，仍使用三列布局。

### 5.4 新建、重命名和删除文件夹

```text
书架右上角 +
→ 新建文件夹
→ 输入名称
→ 创建
```

名称规则：

- 去除首尾空格。
- 1～40 个字符。
- 同级可允许重名，但创建时提示，默认建议避免重名。
- 系统分类名称不可被用户覆盖。

删除文件夹时弹出：

> 删除“想看的漫画”文件夹？其中 12 本漫画会移到“未分组”，漫画、原图和阅读进度不会删除。

### 5.5 把漫画拖进文件夹

交互规则：

1. 长按漫画 350ms 进入拖动。
2. 文件夹作为投放目标高亮并轻微缩小。
3. 在文件夹上停留 600ms，显示“移动到 ××”。
4. 松手后移动成功，底部提示“已移到 ×× · 撤销”。
5. 5 秒内可撤销。

拖动到普通漫画上不能自动创建文件夹，避免误操作。创建文件夹必须由明确入口触发。

### 5.6 多选管理

长按普通漫画或点“管理”进入选择模式：

```text
取消              已选择 6 本              全选

[漫画✓] [漫画✓] [漫画 ]

私密   离线   分组到   加入书单   分享   更多
```

批量操作：

- 移动到文件夹。
- 移出文件夹。
- 加入或移出书单。
- 设为私密/取消私密。
- 置顶/取消置顶。
- 网络漫画离线保存。
- 导出或分享。
- 移到回收站。

本地漫画和网络漫画混选时，不可用的操作置灰并解释原因，例如网络漫画不能“移到本地回收站”。

## 6. 阅读器快速定位设计

### 6.1 当前问题

当前阅读器：

- 使用纵向 `ListView.builder`，可自由连续滚动。
- 底部只有线性进度显示，不能拖动。
- 每次滚动通过线性遍历页面高度估算当前页。
- 600～1000 页时，用户只能反复滑动，定位成本过高。

### 6.2 新增“页码定位器”

用户轻点阅读画面后显示控制层：

```text
┌──────────────────────────────┐
│ ‹ 漫画标题                 ⋮ │
│                              │
│              图片内容     ┃ │ ← 右侧可拖动滑轨
│                         [356]│ ← 拖动时页码气泡
│              图片内容     ┃ │
│                              │
│ 亮度   进度 356/628   ⚙设置 │
└──────────────────────────────┘
```

定位器规则：

- 可点击区域宽度不小于 44dp，实际可见轨道保持纤细。
- 滑块可直接拖到最上方或最下方。
- 点击轨道空白处按该位置跳转，不只是翻一屏。
- 拖动时显示 `356 / 628 · 56.7%`。
- 气泡内显示目标页小缩略图；网络未缓存时显示页码占位，不阻塞拖动。
- 拖动过程中以 50～80ms 节流预览，松手后精确定位。
- 松手后第一张可见图片必须就是目标页。
- 控制层消失后，定位器隐藏，避免影响沉浸阅读。

Flutter 的 `RawScrollbar` 官方支持拖动滑块和点击轨道，本项目可以以它为基础，但需要显式使用同一个 `ScrollController`、开启交互，并叠加页码气泡和按页定位逻辑。

### 6.3 精确定位算法

不同漫画图片高度不同，不能简单使用 `总高度 × 百分比` 后猜页码。建议在页面尺寸已知时预计算前缀和：

```text
pageOffsets[0] = 0
pageOffsets[n] = 前 n 张显示高度 + 图片间距之和
```

实现规则：

- 初始化和屏幕宽度改变时重建 `pageOffsets`，时间复杂度 O(n)。
- 滚动时用二分查找从 offset 找页码，复杂度 O(log n)。
- 拖动定位器时先把滑块比例映射为目标页码，再取该页的精确 offset。
- 旋转屏幕、改变图片间距或适配模式时重建索引。
- 不在拖动时解码 600 张原图，只使用缩略图或文字占位。

### 6.4 顶部、底部和指定页

溢出菜单增加：

- 回到第 1 张。
- 跳到最后 1 张。
- 跳转到指定页。
- 回到上次阅读位置。

“跳转到指定页”接受 `1～总页数`，适合用户已经知道目标页码时使用。

### 6.5 自由滑动保持不变

- 单指上下滑动：连续阅读。
- 双击图片：局部缩放。
- 拖动右侧滑块：快速跨越大量页面。
- 点击页面中央：显示/隐藏控制栏。

快速定位是新增通道，不替换原有自然滚动。

- 单本覆盖可以一键恢复为全局默认。

## 8. 图片顺序编辑器完整方案

### 8.1 先解决发布错位

发布新功能前，必须先构建一个包含 `42d7350` 及后续修复的 APK，让用户真正获得：

- 点选反馈。
- 多选计数。
- 删除确认。
- 可变草稿列表。
- 保存后持久化。
- 取消时不落库。
- 单张长按拖动。

### 8.2 选择规则

- 点按图片：选择/取消选择。
- 长按空白区域后滑过：范围选择。
- 顶部“全选”：选择当前漫画全部页面。
- 再次点击“全选”：清空选择。
- 已选择图片显示蓝色边框、序号和勾选标记。
- 顶部实时显示“已选择 N 张”。

### 8.3 删除规则

```text
选择 1 张或多张
→ 点击删除
→ “删除选中的 N 张图片？”
→ 确认
→ 只从编辑草稿移除
→ 点击保存后数据库才更新
```

- 删除页面引用后不立即抹除物理原图。
- 若该原图仍被其他漫画引用，必须继续保留。
- 若删除的是当前封面，保存时必须把封面字段明确清空，再自动使用新的第一张作为显示回退。
- 取消编辑时，所有删除操作都撤销。

### 8.4 移动和排序

提供四种方式：

1. 正序：按文件名自然顺序重新排。
2. 倒序：反转当前顺序。
3. 长按拖动：适合短距离移动一张或一组图片。
4. 移动到页码：适合 600～1000 页的长距离移动。

多选拖动规则：

- 如果长按的是已选图片，则所有已选图片作为一个块移动。
- 块内顺序保持不变。
- 如果长按的是未选图片，则只拖动该图片，不隐式改变已有选择。
- 放下前显示插入线和目标页码。
- 边缘停留触发自动滚动，但速度有上限，防止失控。

“移动到页码”示例：

```text
已选择 12 张
移动到第 [ 350 ] 张之前
```

### 8.5 编辑器快速滚动

编辑器也增加右侧可拖动定位器，拖动时显示目标页码。否则即使支持拖动排序，用户仍难以在 1000 个缩略图中到达目标位置。

## 9. 私密阅读设计

### 9.1 私密能力分级

“App 数据保存在私有目录”不等于“别人拿到解锁后的手机也看不到”。因此私密阅读分三层：

| 层级 | 保护内容 | 默认 |
|---|---|---|
| 本地私有存储 | 原图不主动进入系统相册 | 已有 |
| 私密书架 | 私密漫画从普通书架和最近阅读隐藏 | 新增，开启私密后生效 |
| 身份验证 | 生物识别或手机锁屏凭据解锁 | 新增，可配置 |

### 9.2 具体行为

- 长按漫画 → “设为私密”。
- 普通书架不显示私密漫画封面、标题和进度。
- “私密书架”入口只显示锁图标和数量是否显示的开关。
- 进入私密书架时调用 Android 系统生物识别/设备凭据。
- App 进入后台超过 30 秒后自动重新锁定，可配置为立即、30 秒、5 分钟。
- 私密页面启用 `FLAG_SECURE`，阻止系统截图和非安全显示；是否允许用户主动截图可做设置项。
- 导出、分享和移出私密区都需要再次验证。
- 私密状态进入完整备份，但网络密码和解锁密钥不进入备份。

### 9.3 不采用的做法

- 不伪装成其他 App。
- 不提供隐藏图标或暗门手势作为首版能力。
- 不自建云账号系统。
- 不把用户 PIN 明文存入数据库。

Android 官方建议使用系统 `BiometricPrompt` 进行生物识别或设备凭据验证，并可使用 Android Keystore 限制密钥必须在用户认证后使用。

## 10. 本地下载、导出、分享和书单

### 10.1 四个动作必须分开

| 动作 | 结果 | 是否产生新文件 |
|---|---|---:|
| 离线保存 | 把网络漫画固定在 App 私有缓存中 | 是，仍在 App 私有目录 |
| 导出到本地 | 生成 CBZ 到用户选择的系统目录 | 是，用户可见 |
| 分享文件 | 通过 Android 分享面板发送临时/导出 CBZ | 是或使用临时文件 |
| 加入书单 | 只改变 App 内的逻辑归类 | 否 |

### 10.2 导出格式

默认导出为 CBZ：

- 页面按当前用户保存后的顺序写入。
- 文件名统一为补零序号，例如 `0001.jpg`、`0002.png`。
- 原图字节不重新编码。
- 保留原扩展名。
- 可写入 `ComicInfo.xml`，包含标题、页数和封面索引。
- 导出前显示预计大小和可用空间。
- 导出完成后显示 SHA-256 或至少校验总页数与总字节数。

### 10.3 用户选择目录

使用 Android Storage Access Framework 让用户选择导出位置，而不是申请宽泛的全盘存储权限。系统可通过 `ACTION_OPEN_DOCUMENT_TREE` 授予用户所选目录的访问权，并可在用户同意后持久保存 URI 权限。

### 10.4 阅读分享

“分享阅读”首版定义为两种：

- 分享漫画文件：发送 CBZ。
- 分享阅读卡片：只包含封面、标题和 `已读 356/628`，不上传原图、不生成公开社交动态。

不在首版加入关注、评论、排行榜或云端社交系统。

## 11. 网络挂载和登录记录

### 11.1 现在是否能成功

当前状态必须按证据拆开说：

| 类型 | 当前验证程度 | 能否宣称完成 |
|---|---|---|
| OPDS | 本地真实 HTTP 服务、发现、首次读取、缓存、断网阅读、解除挂载已验收 | 可以宣称已通过该测试链路 |
| WebDAV | 自动化扫描、读取和缓存测试已有 | 还需目标服务实机复验 |
| SMB/NAS | 连接、扫描和下载代码已实现 | 不能在真实 NAS 验收前宣称全面成功 |

所以答案是：**挂载架构和主要代码已经存在，但“所有挂载最终都可靠成功”还没有得到足够的真实设备证据。SMB/NAS 必须在用户实际 NAS 或同类设备上完成一次完整验收。**

### 11.2 “直接读”的准确定义

当前远程压缩包流程是：

```text
挂载书库
→ 浏览远程漫画目录
→ 首次打开时下载整本压缩包到受控缓存
→ 在缓存中解压并阅读
→ 阅读记录只写本机
```

这属于“用户无需手动下载和导入”的直接阅读体验，但不是“手机完全不落缓存”的纯流式挂载。

推荐后续按能力分层：

- 远程散图目录：按页读取并预取附近 2～3 页。
- Komga/Kavita 页面接口：按页请求。
- WebDAV/SMB 上的 CBZ/CBR：默认整包缓存；只有服务可靠支持 Range/随机读取时再优化。
- 断网时已缓存页面可读，未缓存页面显示重试。

### 11.3 登录和认证记录

不保存“密码历史”，只保存连接配置和状态：

```text
书库名称
协议类型
服务地址 / 主机
根目录
用户名
最后连接成功时间
最后同步时间
最后错误类型
当前状态：已连接 / 需重新登录 / 离线 / 服务不可达
```

密码、Token、SMB 域凭据放入 Android 安全存储。普通数据库只保存非秘密配置和用户名。完整备份可以带网络源配置，但不得带密码；恢复后显示“需要重新登录”。

### 11.4 状态与恢复操作

每个网络书库提供：

- 测试连接。
- 立即同步。
- 编辑地址和根目录。
- 重新登录。
- 清除全部本地缓存。
- 解除挂载。
- 查看最后错误。

错误需翻译为用户可行动的文案，例如：

- `401/403`：登录已失效，请重新输入账号密码。
- 域名无法解析：无法找到服务器，请检查地址或网络。
- 超时：服务器响应超时，可稍后重试。
- 证书错误：连接证书无效，不允许静默忽略。
- SMB 共享不存在：请检查共享名和根目录。

## 12. 数据模型建议

下一次数据库版本建议从 v3 升到 v4，只做增量迁移。

### 12.1 文件夹

```sql
CREATE TABLE shelf_folders (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  sort_index INTEGER NOT NULL,
  is_private INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

ALTER TABLE comics ADD COLUMN folder_id TEXT;
ALTER TABLE comics ADD COLUMN is_private INTEGER NOT NULL DEFAULT 0;
ALTER TABLE comics ADD COLUMN is_pinned INTEGER NOT NULL DEFAULT 0;
ALTER TABLE comics ADD COLUMN read_status TEXT NOT NULL DEFAULT 'unread';
```

`folder_id` 为可空字段。旧漫画迁移后全部为 `NULL`，即进入“未分组”，不改变原书架顺序。

### 12.2 书单

```sql
CREATE TABLE reading_lists (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  sort_index INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE reading_list_items (
  list_id TEXT NOT NULL,
  comic_id TEXT NOT NULL,
  sort_index INTEGER NOT NULL,
  PRIMARY KEY (list_id, comic_id)
);
```

### 12.3 阅读器设置

全局默认可继续进入 `settings` 表；单本覆盖增加：

```sql
CREATE TABLE comic_reader_preferences (
  comic_id TEXT PRIMARY KEY,
  brightness REAL,
  image_gap REAL,
  fit_mode TEXT,
  keep_screen_on INTEGER,
  updated_at TEXT NOT NULL
);
```

### 12.4 网络连接状态

`network_sources` 增加可空字段：

```text
last_connected_at
last_synced_at
last_error_code
last_error_message
auth_state
```

不得增加 password、token 或 cookie 字段。

### 12.5 备份格式

- 备份 manifest 从 v2 升到 v3。
- 新增文件夹、书单、成员、私密状态和单本设置。
- 不包含安全存储中的网络凭据和私密解锁密钥。
- 恢复旧 v1/v2 备份时使用默认未分组、非私密状态。

## 15. 验收标准

### 15.1 书架和分组

- 360dp 和 411dp 手机竖屏均显示三列。
- 新建、重命名、排序和删除文件夹后，重启 App 状态不变。
- 拖一本漫画进文件夹后，封面、页数、顺序和进度不变。
- 删除文件夹后，漫画进入“未分组”，文件数和原图哈希不变。
- 1000 本测试书架滚动无明显持续卡顿。

### 15.2 编辑器

- 单击任意图片可选中和取消。
- 可同时选择至少 100 张并删除。
- 删除后点取消，数据库完全不变。
- 删除后点保存，重新进入仍保持结果。
- 删除当前封面后，不再保留失效封面引用。
- 单张拖动、多选块移动和页码移动均保持预期顺序。
- 1000 张编辑页不一次解码全部高清原图。

### 15.3 阅读定位

- 30、300、600、1000 张漫画分别测试。
- 滑块可直接拖到第 1 张和最后 1 张。
- 松手后首个可见页面与气泡页码一致。
- 拖动反馈在 100ms 内更新，松手后 500ms 内完成定位；低端设备可单独记录但不得冻结。
- 修改图片间距、旋转屏幕后定位仍准确。
- 阅读进度重启后恢复到相同页和合理页内位置。

### 15.4 私密

- 私密漫画不出现在普通书架、搜索建议和最近阅读。
- 未验证身份不能进入私密书架、导出或分享私密漫画。
- App 进入后台后按设定时间重新锁定。
- 启用安全显示后系统截图为空白或被阻止。
- 完整备份不包含解锁密钥和网络密码。

### 15.5 导出与分享

- 导出的 CBZ 页数和当前漫画页数一致。
- 包内顺序与编辑后顺序一致。
- 每张图片导出前后哈希一致。
- 目标目录由系统选择器授权，不申请不必要的全盘权限。
- 取消导出后无损坏的半成品留在目标目录。

### 15.6 网络挂载

- WebDAV、OPDS、SMB 各使用至少一个真实服务完成登录、扫描、打开、断网、重连、重新认证和解除挂载。
- 账号密码不出现在数据库导出、日志、备份、Git diff 或 GitHub Release。
- 解除挂载后远端文件哈希和数量不变。
- 恢复备份后书库配置存在，但显示“需要重新登录”。
- 600 页网络漫画的快速定位与本地漫画一致。

### 15.7 原位升级

- 从 GitHub v1.1.0 APK 覆盖安装最终版。
- 漫画数、页面数、封面、顺序、进度、备份和原图哈希全部不变。
- 新字段使用安全默认值，旧漫画全部进入“未分组”。
- 最终 APK 可从私人 GitHub Release 下载，附 SHA-256 和回退说明。

## 16. 风险与处理

| 风险 | 处理 |
|---|---|
| 三列后标题空间不足 | 单行省略，完整标题在详情页显示 |
| 拖动与普通滚动冲突 | 350ms 长按进入拖动，拖动目标高亮 |
| 600 页定位时频繁解码缩略图 | 预生成小缩略图、节流更新、网络缺图用页码占位 |
| 图片高度不同导致跳页不准 | 使用页高前缀索引和按页映射，不只按百分比猜 offset |
| 多选移动后位置算法错误 | 块内顺序固定，先移除再按目标索引插入，增加边界测试 |
| 私密漫画通过系统最近任务泄露 | 私密区域使用 `FLAG_SECURE`，后台立即遮挡 |
| 生物识别不可用 | 回退到系统设备 PIN/图案/密码，不自存明文 PIN |
| 导出占用双倍空间 | 导出前估算空间，流式写包，失败清理临时文件 |
| 网络登录过期 | 持久化非秘密错误状态，提供明确重新认证入口 |
| SMB 设备差异 | 以真实 NAS 作为发布门槛，不用单元测试代替硬件验收 |
| 升级签名丢失 | 离线备份签名密钥和证书指纹，禁止随意更换 |

---

## 17. 本稿建议的默认决策

为避免实现时反复摇摆，建议直接采用以下默认值：

1. 手机书架默认三列；平板响应式增加列数。
2. 文件夹为唯一物理位置，书单允许重复收录。
3. 删除文件夹永远不删除漫画。
4. 私密漫画默认从普通书架、最近阅读和搜索中隐藏。
5. 私密解锁默认使用生物识别或手机锁屏凭据。
6. 阅读器使用右侧竖向定位器，并保留底部页码。
7. 定位器拖动时显示页码、百分比和缩略图。
8. 多选图片可作为连续块移动，并提供“移动到页码”。
9. 阅读亮度只影响 App，不永久修改系统亮度。
10. “网络直接阅读”允许透明缓存，不承诺零缓存。
11. 网络密码不进入完整备份，恢复后要求重新登录。
12. 分享默认走 Android 系统分享面板，不自建社交系统。
13. 导出默认 CBZ，不重新编码图片。
14. UI 风格冻结，只增加必要功能组件。

## 18. 评判结论

### 18.1 产品价值

这一轮新增能力不是零散堆按钮，而是在补齐私人漫画阅读器的三个核心短板：

- 漫画多时能整理。
- 页数多时能定位。
- 内容私密时能真正保护。

三列书架和文件夹解决“找书”，快速定位解决“找页”，编辑器多选与精确移动解决“整理页”，私密锁和受控分享解决“保护与带走数据”。四者互相配合，方向成立。

### 18.2 最大注意点

最需要避免的是再次出现“设计文档写已完成、源码确实有、但用户下载到的 APK 仍没有”的交付错位。后续所有功能状态必须固定使用四级口径：

```text
已设计
已实现源码
已通过测试
已进入 GitHub 可下载 Release APK
```

只有达到第四级，才对用户说“已经可以用了”。

### 18.3 最终判断

方案可行，难度中高，建议按阶段 LOOP 实施，不改变现有 UI 风格。第一步不是立即做大改版，而是先发布含编辑器修复的 v1.1.1 APK；随后再用可回退的数据库迁移进入分组、快速定位、私密和网络强化。这样既满足最终完整能力，也保住现有数据和每个回退点。

## 19. 只面向私人使用的追加建议

### 19.1 私人版的产品取舍

不商业化不是“功能可以随便堆”，而是可以把资源全部用在一个目标上：**让你自己的漫画库长期可读、可找、可恢复，不需要照顾广告、增长、付费和社交。**

因此私人版应该主动舍弃：

- App 账号和自建用户系统。
- 广告、订阅、商城、积分和付费墙。
- 埋点、遥测、崩溃自动上报和阅读行为统计上传。
- 好友、评论、排行榜、公开书单和推荐信息流。
- DRM、在线许可证和设备数量限制。
- 为了“活跃度”而增加的签到、任务和消息推送。
- 自动把漫画、封面或阅读记录上传到 GitHub。

私人版应该重点加强：

- 直接访问自己的手机目录、NAS 和私人书库。
- 长漫画的查找、定位、书签和阅读恢复。
- 数据完整性检查、修复和灾难恢复。
- 可选择的加密备份。
- 对个人阅读习惯有用的设置，而不是通用商业功能。

非商业使用也不改变第三方代码、图标和品牌素材的许可证或版权边界，所以仍采用“借鉴交互、保持自己的 UI”，不复制微信读书的专有素材。

### 19.2 本地文件夹只读挂载

这是我认为最应该追加的能力。除了“把图片复制进 App”，还应允许把手机或外置存储中的一个目录直接挂成书源：

```text
添加书源
→ 本地文件夹
→ 用系统目录选择器选择 Manga/
→ App 保存该目录的持久访问权限
→ 扫描子目录和漫画压缩包
→ 在书架中直接阅读
```

建议同时保留两种模式：

| 模式 | 文件位置 | 优点 | 风险 |
|---|---|---|---|
| 导入到私人书架 | 复制到 App 私有目录 | 最稳定，源文件删除后仍可读 | 占用额外空间 |
| 本地文件夹挂载 | 原地只读 | 不复制，适合大容量 SD 卡/共享目录 | 文件移动或授权失效后会离线 |

挂载规则：

- 使用 Android Storage Access Framework 的目录授权，不申请全盘文件权限。
- 默认只读，绝不改名、移动或删除用户目录中的文件。
- 子目录可以自动映射为候选文件夹，但只在用户确认后写入书架分组。
- 支持手动“重新扫描”，首版不依赖不稳定的实时文件监听。
- 文件移动后尽量通过大小、修改时间和内容指纹重新匹配，保留阅读记录。
- 授权被系统撤销时显示“需要重新选择目录”，不把漫画误判为已删除。
- 可以把某一本挂载漫画“固定离线”或“正式导入”，转成 App 私有副本。

### 19.3 收件箱目录

在本地文件夹挂载之上增加一个可选的“漫画收件箱”：

```text
用户把 CBZ/ZIP 放进指定目录
→ 打开 App 或手动扫描
→ 显示待处理队列
→ 用户确认名称、目标文件夹和顺序
→ 导入或只读挂载
```

它适合日常从电脑传漫画到手机，但首版不应静默自动导入，避免误把临时文件、半下载文件或错误压缩包加入书架。

### 19.4 书签、标记和本地阅读历史

600 页漫画只有快速滑块仍不够，用户还需要记住“哪几页以后想回来”。建议增加：

- 当前页一键添加书签。
- 书签可写一句本地备注，例如“剧情转折”“喜欢的画面”。
- 书签列表显示页码、缩略图、创建时间和备注。
- 书签点击后精确跳页。
- 一本漫画可标记“未开始、阅读中、已读完、搁置”。
- 最近阅读历史只保存在本机，可按漫画或日期清除。
- 私密漫画的书签和历史只在私密区解锁后显示。

书签只记录 `comic_id + page_id + note`，不复制图片，也不影响图片顺序。页面被删除时，书签进入“失效书签”提示，由用户选择删除或重新定位。

### 19.5 搜索、筛选和元数据

书架增长后，文件夹不能代替搜索。建议搜索范围包括：

- 漫画标题。
- 作者、系列、卷号。
- 用户标签。
- 文件夹和书单名称。
- 本地/网络来源。
- 未读、阅读中、已完成和搁置状态。
- 已离线、仅网络、私密、置顶。

元数据来源按优先级：

```text
用户手动修改
> ComicInfo.xml
> 压缩包名称
> 上级目录名称
> 原文件名
```

App 可以建议“这些漫画可能属于同一系列”，但不能未经确认自动移动或重命名。

### 19.6 导入任务中心

大型压缩包和多包导入不应只依靠一个短暂进度弹窗。建议增加持久任务中心：

- 排队显示每个压缩包的名称、页数、进度和目标漫画。
- 支持暂停、取消和失败项重试。
- App 切到后台或被系统回收后，重新打开能说明任务是完成、中断还是待恢复。
- 每个压缩包使用独立临时目录，成功后再原子提交到漫画末尾。
- 失败的包不影响前面已经成功提交的包。
- 显示空间不足、损坏文件、加密包、异常压缩比和不支持格式等明确原因。
- 导入完成后生成本地报告，但不上传任何文件名或统计。

压缩包密码支持建议列入后续版本：

- 首次遇到加密包时由用户输入。
- 默认只在当前任务内存中使用，不保存密码。
- 用户主动选择“记住”时才写入 Android 安全存储。
- 不支持或密码错误时不反复暴力尝试。

### 19.7 数据健康与修复中心

私人漫画库可能保存多年，比增加新动画更重要的是能够知道数据有没有损坏。设置中心建议增加“数据健康”：

```text
数据健康
├── 数据库结构与迁移状态
├── 漫画、页面引用和原图数量
├── 缺失原图
├── 失效封面
├── 无引用原图
├── 缩略图缺失或损坏
├── 网络目录授权失效
├── 网络缓存一致性
└── 最近一次完整校验时间
```

检查与修复分开：

- “检查”永远只读，可以随时运行。
- “重建缩略图”和“重建索引”属于可恢复操作。
- “删除无引用原图”继续要求单独确认。
- 原图哈希校验支持快速抽查和完整校验两种模式。
- 完整校验可以在充电时运行，避免大量耗电。
- 修复前自动创建数据库快照和变更清单。

### 19.8 加密备份与自动轮换

当前完整备份包含私人原图，单纯 ZIP 不适合长期放在容易被其他人访问的位置。建议新增可选的加密 `.mangabackup`：

- 使用成熟的认证加密方案，例如 `AES-256-GCM`。
- 密钥由用户密码通过合适的 KDF 派生，例如 `Argon2id`。
- 密码不写入备份、不写入日志，也不上传 GitHub。
- 忘记密码时无法恢复，创建时必须明确提示。
- 恢复前先验证认证标签和清单，不边解密边覆盖现有数据。

自动备份只写入用户明确选择的本地目录或 NAS：

- 每日增量状态备份：数据库、设置、分组、书签和进度。
- 定期完整备份：原图与全部清单。
- 默认保留最近 3 个完整备份和 7 个状态备份，数量可配置。
- 每次备份完成后执行可读性校验并记录结果。
- 至少保留一份不与手机同盘的备份。

### 19.9 源码、APK 与私人漫画数据分离

GitHub 私有仓库只保存：

- 源码。
- 测试。
- 产品和设计文档。
- 不含私人内容的设计参考图。
- Release APK、SHA-256 和回退说明。

GitHub 仓库不保存：

- 用户导入的漫画原图或压缩包。
- `.mangabackup` 数据备份。
- 网络书库密码、Token、Cookie 或证书私钥。
- 签名密钥原文件。
- 带真实服务器地址和用户名的调试日志。

即使仓库是私有的，也不建议把私人漫画数据直接提交到 Git。Git 不是大容量私人媒体备份工具，而且文件一旦进入提交历史，后续清理比普通文件删除复杂得多。私人数据应使用本地加密备份、NAS 或用户自己控制的存储。

### 19.10 更适合漫画的阅读方式

纵向连续阅读继续作为默认模式，同时建议逐步增加：

- 单页横向翻页。
- 从右向左翻页，适配日漫。
- 横屏双页显示，并可设置封面是否单独成页。
- 长图连续模式。
- 双页跨页图识别后整体显示，不自动切断。
- 虚拟裁切白边，只改变显示，不修改原图。
- 音量键翻页或小幅滚动，可在设置中关闭。
- 自定义点按区域：左侧、中央、右侧分别执行上一页、显示控制栏、下一页。

这些模式必须共用同一页码、书签和进度模型，不能为每种阅读方式保存互相冲突的进度。

### 19.11 重复漫画和版本识别

现有内容哈希能去重单张图片，后续可增加“漫画级指纹”：

- 页数。
- 页面哈希序列。
- 总字节数。
- `ComicInfo.xml` 标识。
- 来源路径和远端 ETag。

用途：

- 导入前提示“可能已经存在”。
- 识别同一本漫画的不同压缩格式。
- 网络文件移动后重新关联原阅读记录。
- 比较两个版本缺少或新增了哪些页面。

默认只提示，不自动合并或删除。任何合并都先展示差异，并保留回退点。

### 19.12 隐私安全的本地诊断包

为了以后排查“某台手机能复现、开发机不能复现”的问题，建议允许用户手动生成诊断包：

- App 版本、Android 版本、设备架构。
- 数据库 schema 版本和匿名数量统计。
- 最近一次导入或挂载错误类型。
- 缓存、缩略图和可用空间状态。
- 测试连接的状态码和耗时。

默认删除或替换：

- 密码、Token、Cookie。
- 真实服务器地址和用户名。
- 漫画标题、文件名和绝对路径。
- 漫画封面、页面和备份内容。

诊断包只在用户手动选择“导出诊断”时生成，不自动上传。

### 19.13 私人版不建议现在加入的能力

以下能力投入大、长期维护重，对私人使用价值有限，建议不做：

- 自建云同步服务器。
- GitHub Token 登录和 App 内自动访问私人 Release。
- 在线内容搜索、漫画源爬虫和公共书城。
- 社交阅读、评论和公开分享社区。
- AI 自动推荐和阅读行为画像。
- 默认开启的 OCR、翻译或图片上传。
- 无限层级文件夹。
- 自动修改原文件名、目录和压缩包内容。
- 自动删除“疑似重复”的漫画。

如果以后需要 OCR 或翻译，优先采用本机可选模块，并且明确显示正在处理哪些图片。

### 19.14 建议纳入版本路线

为了避免 v1.2 失控，建议按价值和风险分层：

| 阶段 | 追加内容 | 原因 |
|---|---|---|
| v1.2 架构预留 | 本地文件夹书源、书签表、任务表、健康检查接口、加密备份版本字段 | 现在预留可避免后续反复迁移 |
| v1.2 首发 | 本地文件夹挂载、书签、基础搜索、只读健康检查 | 对私人使用价值最高且不改变 UI 主风格 |
| v1.2.x | 收件箱、导入任务中心、诊断包、漫画级重复提示 | 可在核心稳定后增量交付 |
| v1.3 | 加密自动备份、横向/右到左/双页阅读、加密压缩包 | 价值高但测试面更大 |
| 按需再做 | SFTP、离线 OCR、本地翻译 | 只有真实需求出现后再承担维护成本 |

我的最终建议是：**私人版不需要做成“小型商业阅读平台”，而要做成“能直接接入你的目录和 NAS、能快速找到任何一本和任何一页、数据十年后仍可恢复”的个人漫画资料库。**
