# 拾画阁 v1.3 品牌、书架交互与低占用存储改版方案

> 文档性质：实施前设计与技术方案，不代表代码已经完成
>
> 目标版本：`v1.3.0+4`
>
> 日期：2026-08-30
>
> 基线版本：私人书架 `v1.2.0` / 数据库 schema 5 / 备份 manifest 3
>
> 输入依据：用户本轮提供的 4 张视觉参考图、现有 v1.2 产品文档、源码与 Android 验收记录

## 0. 结论先行

本轮建议把 App 的对外名称正式改为 **“拾画阁”**，保留现有蓝白、克制、内容优先的视觉基线，再把参考图中真正有价值的部分纳入现有产品：

1. 书架顶部采用“搜索—标题—导入/选择—分类”的清晰层级。
2. 分组在主书架中必须以带外框的 2×2 四宫格封面出现，而不是只在移动弹窗中出现。
3. 书单、文件夹、私密区等内部状态统一纳入返回栈；系统侧滑返回不再直接退出 App。
4. 主书架增加明确的“整理书架”模式，漫画和分组都能拖动排序，漫画还能拖入分组。
5. 设置页取消常驻的大滑杆；主书架快速滚动条与右上角菜单彻底避让。
6. 4GB 书库不再只有“复制全部原图”一种选择，新增“原地挂载”和“压缩包直读”两种无损、低占用模式。

整体难度为 **中高，4/5**。改名、图标、返回行为和设置页属于低到中等难度；真正需要认真设计和实机验证的是“混合书架重排”“Android SAF 原地挂载”“压缩包按需读取、缓存与卸载恢复”。

本轮只产出方案，不立即修改源码、版本号、图标或 GitHub Release。实施时必须延续现有原位升级规则，不能以重装或清库换取改版。

## 1. 本轮范围

### 1.1 必须完成

- App 可见名称统一改为“拾画阁”。
- Android 桌面名称、任务切换页名称、App 内标题和关于页名称同步更新。
- 使用第一张参考图的图标视觉，重新制作合格的 Android 自适应图标资源。
- 主书架保留三列，并按第三、四张参考图重组顶部信息层级。
- 分组在主书架和“移动到分组”弹层中都显示 2×2 四宫格真实封面。
- 修复书单/文件夹/私密区侧滑返回直接退出 App。
- 主书架支持持久化拖动排序；漫画可拖入分组。
- 设置页不再常驻显示横跨整行的“图片间距”滑杆。
- 主书架快速滚动不遮挡右侧菜单和操作入口。
- 新增针对 4GB 级书库的低占用导入/挂载方案。
- 升级不改变现有漫画、原图、顺序、封面、阅读进度、书签、书单、分组和备份。

### 1.2 保持不变

- 包名继续为 `com.shitmof.private_manga_reader`。
- 使用与 v1.2.0 相同的签名密钥，保证可原位升级。
- 本地优先、无账号、无广告、无社交、无遥测。
- 原图不重编码、不降低画质。
- 单本图片编辑器现有的多选、删除、移动、封面和保存能力继续保留。
- 阅读器现有的纵向连续阅读、页码滑块、右侧快速定位、亮度和书签继续保留。
- WebDAV、OPDS/Komga/Kavita、SMB/NAS 继续只读，阅读记录留在本机。
- GitHub 私有仓库只保存源码、文档和 Release APK，不上传用户漫画。

### 1.3 明确不做

- 不加入会员、书城、付费、推荐流、有声书和社交模块。
- 不逐像素复制微信读书的页面、品牌、图标或专有素材。
- 不因为是私人项目就直接复制许可证不兼容的第三方代码。
- 不自动删除现有 4GB 私有原图，不在后台静默“瘦身”。
- 不使用 `MANAGE_EXTERNAL_STORAGE` 获取全盘权限；本地挂载使用用户明确授权的目录。
- 不承诺 App 私有目录能在卸载后保留。Android 会删除应用专属存储，卸载恢复必须依靠外部原文件或外部备份。

## 2. 参考图的取舍

### 2.1 第一张图：品牌

采用：

- 名称“拾画阁”。
- 米白、暖灰、深海军蓝的图标气质。
- “多层画册 + 图片 + 书签”的核心图形语义。

不直接采用：

- 图标下方的“拾画阁”大字不能进入 Launcher 图标位图。
- 整张 1280×1280 参考图含背景、阴影和文字，不能直接缩成 Android 图标，否则桌面显示会过小、模糊并产生双重底板。

实施时应从参考图重建一份无文字的 1024×1024 主图，并拆分：

```text
assets/branding/
├── shihuage_icon_master.png       # 1024×1024，无文字
├── shihuage_icon_foreground.png   # 自适应图标前景
├── shihuage_icon_monochrome.png   # Android 13 主题图标
└── shihuage_brand_reference.jpg   # 仅设计参考，不参与打包
```

建议自适应图标背景使用暖米白 `#F4EFE8`，前景保留深蓝书页、米色夹层和蓝色书签。前景主体必须落在 Android 自适应图标安全区内，避免圆形、方圆形和水滴形遮罩裁掉书签或后层漫画页。

### 2.2 第二张图：分组

采用：

- 分组条目显示最多 4 本封面的 2×2 拼图。
- 显示分组名称与“共 N 本”。
- “移动到分组”使用半高底部弹层，顶部有返回/收起、新建分组。

强化：

- 主书架中的分组也使用同一套四宫格语言，不能只在移动弹层中出现。
- 四个格位始终存在；少于 4 本时使用空白纸页占位，不能让 1～3 本封面被拉伸成不规则布局。
- 私密分组不显示真实封面，只显示四个中性占位格和锁图标。

### 2.3 第三、四张图：书架层级

采用：

- 顶部搜索入口。
- “书架”标题与“导入 / 选择”并列。

- 三列内容网格。
- 导入使用清晰的单一弹层，而不是把所有动作藏在三点菜单里。

不采用：

- 书城、会员导入额度、有声书、个人中心等商业产品模块。
- 与本项目无关的电子书格式承诺。
- 参考图的品牌色、专有文案和完整底部导航外观。

## 3. 现状检视与根因

| 问题 | 现有源码事实 | 根因 | 处理结论 |
|---|---|---|---|
| 书单内侧滑返回退出 App | `LibraryScreen` 只修改 `_readingListId`，没有 `PopScope` 或独立路由 | Android 认为已在根路由 | P0 修复 |
| 顶部返回正常、侧滑异常 | 顶部按钮手动把 `_readingListId` / `_folderId` 清空 | 两套返回逻辑没有统一 | 集中为一个返回状态机 |
| 设置页“大拉杆”影响观感 | “图片间距”把 `Slider` 直接放在 `ListTile.subtitle` | 控件横跨整张卡片且始终可见 | 改成数值行，点击后再调整 |
| 右侧滚动条影响菜单 | 主书架直接包裹 `Scrollbar(interactive: true, thickness: 5)` | 没有独立控制器、显隐和安全边距策略 | 改成瞬时窄滑块与独立热区 |
| 主书架不能自由移动漫画 | `reorderComics()` 后端已经存在，三列 `_LibraryGrid` 没有调用 | UI 只有“拖入文件夹”，没有根书架重排模式 | 增加整理模式并补齐混合节点排序 |
| 分组存在但视觉不够明确 | `_FolderCard` 已取最多 4 本封面，但只渲染实际数量 | 少于 4 本时四宫格结构消失；移动弹层仍是普通文件夹图标 | 固定四格 + 外框 + 弹层同构 |
| 导入 4GB 后空间增长明显 | `ImportService` 把源文件复制到临时文件，再移动到私有 `assets` | 保留源文件时相当于至少保存两份 | 增加原地挂载和容器直读 |
| 压缩包导入后占用可能大于包本身 | 当前逐页解压，再把每页作为永久原图导入 | 压缩包与解压页可同时存在 | 增加只保留容器、页面按需解码 |

现有删除能力并非缺失：v1.2.0 已有页面多选删除、漫画回收站和永久清理。本轮只做回归保护，不重写删除语义。

## 4. 新的信息架构

### 4.1 一级导航

推荐使用 3 个底部入口：

```text
书架 ｜ 网络 ｜ 设置
```

- “书架”是默认首页，包含本地漫画、分组、书单和私密区。
- “网络”承载 WebDAV、OPDS、SMB/NAS，不再藏在主书架三点菜单。
- “设置”承载阅读、外观、存储、备份、数据健康。
- 不新增“发现、书城、社区、我的”。

底部导航只解决一级信息架构，不改变阅读流程。进入漫画详情、编辑器或阅读器后隐藏底部栏，保留沉浸体验。

### 4.2 主书架线框

```text
┌────────────────────────────┐
│ 🔍 搜索漫画、分组、书单     │
│                            │
│ 书架             ＋导入  ✓选择 │
│ 全部  最近  置顶  未读  书单  私密 →│
│                            │
│ [分组]   [漫画]   [漫画]    │
│ [漫画]   [分组]   [漫画]    │
│ [漫画]   [漫画]   [漫画]    │
│                         ▏  │
├────────────────────────────┤
│  书架        网络        设置 │
└────────────────────────────┘
```

### 4.3 顶部区域

- 搜索框高度 44dp，默认不自动弹出键盘；点击进入搜索页。
- 搜索范围包括漫画名、分组名、书单名和本地元数据。
- 标题行左侧为“书架”，右侧为“导入”和“选择”。
- “导入”打开统一导入弹层。
- “选择”进入批量选择模式。
- 不再依赖右上角三点菜单承载关键功能。

### 4.4 筛选栏

默认顺序：

```text
全部 ｜ 最近 ｜ 置顶 ｜ 未读 ｜ 书单 ｜ 私密
```

- 横向滚动，不换行。
- 选中项使用现有蓝色，不引入新的品牌色。
- “书单”点击后进入书单列表；系统返回回到书架根目录。
- 私密区进入前保持现有系统身份验证。

## 5. 分组卡片与移动弹层

### 5.1 主书架分组卡

分组与漫画占用相同的三列格位，但视觉上必须一眼可辨：

```text
┌────────────┐
│ ┌──┐ ┌──┐ │
│ │封│ │封│ │
│ └──┘ └──┘ │
│ ┌──┐ ┌──┐ │
│ │封│ │封│ │
│ └──┘ └──┘ │
└────────────┘
想看的漫画  ⋯
12 本
```

规格：

- 外框圆角 14dp，1dp 低对比描边，内部 6dp 留白。
- 四格固定，格间距 3dp；封面使用 `BoxFit.cover`。
- 少于 4 本时，空位显示带轻微纸张纹理的中性占位，不使用虚假漫画图。
- 空分组显示 4 个占位格，而不是单个大文件夹图标。
- 分组名称单行省略，第二行显示 `N 本`。
- 私密分组显示锁，不渲染真实封面。
- 长按或三点菜单提供重命名、设为私密、移出全部、删除分组。
- 删除分组只把成员移到书架根目录，不删除漫画和原图。

### 5.2 “移动到分组”弹层

弹层采用第二张参考图的层级，但使用本项目视觉：

```text
⌄             移动到分组            新建分组

[四宫格]  想看的漫画
          共 12 本

[四宫格]  学习
          共 2 本

[四宫格]  收藏画面
          共 21 本

🏠 移到书架根目录
```

- 支持单本和多选漫画。
- 分组列表本身可滚动，最多占屏幕高度 70%。
- 当前所在分组显示勾选状态。
- 移动成功后显示 5 秒“撤销”。
- 新建分组后立即成为选中目标，但仍需明确确认移动。

## 6. 主书架整理与拖动

### 6.1 为什么增加独立“整理书架”模式

普通模式同时承担“打开漫画、长按选择、拖入分组、拖动排序”会产生手势冲突。建议把高风险移动集中到显式整理模式：

```text
选择 → 整理书架
```

进入后：

- 漫画和分组右上角出现轻量拖动手柄。
- 长按任意卡片即可拖动排序。
- 拖到分组上停留 500ms，分组高亮；松手后移入分组。
- 拖到屏幕顶部/底部 48dp 热区时自动滚动。
- 顶部固定显示“取消 / 整理书架 / 保存”。
- 所有变更先写入内存草稿，点“保存”才事务提交。
- 取消、系统返回或异常退出不改变正式顺序。

### 6.2 排序作用域

- 书架根目录：漫画和分组混合排序。
- 某个分组内部：只排序该分组中的漫画。
- 书单：保持书单自己的成员顺序，不改漫画的物理书架位置。
- 智能筛选“最近、置顶、未读”按规则计算，不允许手动排序。

### 6.3 数据模型

当前 `comics.sort_index` 与 `shelf_folders.sort_index` 分属两张表，无法表达“分组和漫画混排”。建议 schema 6 新增统一位置表：

```sql
CREATE TABLE shelf_entries (
  id TEXT PRIMARY KEY,
  parent_scope_id TEXT NOT NULL,
  entity_type TEXT NOT NULL CHECK(entity_type IN ('comic', 'folder')),
  entity_id TEXT NOT NULL,
  sort_index INTEGER NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(parent_scope_id, entity_type, entity_id)
);
```

约束：

- 仅支持一层用户分组，不做无限嵌套。
- `parent_scope_id='__root__'` 表示书架根目录，其他值为分组 ID，避免 SQLite 的 `NULL` 唯一约束留下重复位置。
- `folder` 只能出现在根目录，禁止分组套分组。
- v1.2 升级时按“现有文件夹顺序在前、根目录漫画顺序在后”生成初始 `shelf_entries`，不改旧字段和旧数据。
- 待 schema 6 稳定并通过两次正式发布后，旧排序字段才可考虑降级为兼容字段；v1.3 不删除。

## 7. 返回导航修复

### 7.1 统一返回优先级

无论点击顶部返回、Android 三键返回还是系统侧滑返回，都调用同一个状态机：

| 当前状态 | 第一次返回 |
|---|---|
| 弹窗、底部弹层、搜索建议 | 关闭最上层覆盖物 |
| 选择模式 | 退出选择模式并清空选择 |
| 整理书架且有未保存修改 | 弹出“保存 / 放弃 / 继续整理” |
| 书单 | 回到书架根目录 |
| 分组内部 | 回到书架根目录 |
| 私密区 | 锁定私密区并回到书架根目录 |
| 漫画详情、设置、网络书库 | 回到书架根目录 |
| 阅读器 | 回到漫画详情；再次返回到书架 |
| 图片编辑器 | 有修改时确认，无修改时回漫画详情 |
| 书架根目录 | 才允许退出 App |

用户明确要求的关键验收是：**在书单内侧滑返回时只能回主书架，不能退出 App。**

### 7.2 Flutter 实施方式

- `LibraryScreen` 外层增加 `PopScope`。
- 当 `_readingListId`、`_folderId`、选择模式或私密范围存在时，`canPop` 为 `false`。
- 在 `onPopInvokedWithResult` 中调用统一 `_handleBack()`，而不是复制顶部按钮逻辑。
- 顶部返回按钮也调用 `_handleBack()`。
- 设置、网络、详情和阅读器继续使用真实 `Navigator` 路由。
- Android 15/16 实机验证预测性返回，确认预览目标与实际返回一致。

Flutter 官方说明指出，`PopScope.canPop` 应提前决定是否允许路由弹出；`onPopInvokedWithResult` 会在返回处理后收到结果。因此不能等路由已经退出后再尝试恢复书单状态。

## 8. 滚动条与设置页改造

### 8.1 主书架快速滚动

保留快速到顶/到底能力，但不常驻一根显眼滑杆：

- 为书架网格提供专用 `ScrollController`。
- 滑块默认隐藏，滚动或触摸右侧热区时淡入。
- 视觉宽度 3dp，触摸热区 24dp，视觉与可点击区域分离。
- 顶部避让 AppBar 与筛选栏，底部避让底部导航。
- 不在内容不足 1.5 屏时显示。
- 拖动时在滑块左侧显示“第 42 / 386 项”。
- 右上角菜单、导入和选择按钮不处于滑块热区内。
- 书架快速滚动、编辑器页码移动、阅读器页面定位分别实现，不共享一个大而笨重的控件。

### 8.2 设置页“大拉杆”

当前“图片间距”把滑杆常驻在设置卡片中。建议改为：

```text
图片间距                         12 dp  ＞
```

点击后打开紧凑底部弹层：

```text
图片间距
紧凑  8 dp   ｜   标准 12 dp   ｜   宽松 16 dp
                  －  12  ＋
```

- 默认使用三个预设值，保留加减微调。
- 滑杆如仍保留，只在该弹层内部短暂出现。
- 设置列表本身使用普通 `ListView`，不显示可交互的常驻滚动条。
- 设置项右侧值和箭头保持可点击，不被任何滚动控件覆盖。

```text
导入到拾画阁

🖼  从相册选择图片
📁  从本地选择图片
📦  导入漫画压缩包
```

说明：

- 不显示会员、导入额度和付费文案。
- 图片与压缩包继续支持多选，App 不设置单批 100 张限制。
- 多个压缩包继续按系统选择队列顺序追加；包内按 `ComicInfo.xml` 或自然数字顺序。
- 导入前必须显示“保存方式、预计新增占用、临时峰值、是否能在卸载后找回”。

## 10. 4GB 书库的低占用方案

### 10.1 为什么不能只靠压缩图片

用户不希望牺牲原画质，正确方向不是把原图统一改成 JPEG，而是避免重复保存同一份数据。当前导入模式在源文件仍保留时，会形成：

```text
原目录 / 原压缩包
+ App 私有 assets 原图
+ 缩略图
+ 导入临时文件
```

所以 4GB 源文件可能带来接近 8GB 或更高的阶段性占用。新方案将“组织信息”和“内容物理位置”分离。

### 10.2 三种正式模式

| 模式 | 永久新增原图占用 | 源文件移动后 | 卸载后 | 推荐场景 |
|---|---:|---|---|---|
| 原地挂载 | 约 0，仅索引/缩略图/缓存 | 需要重新定位 | 原文件仍在，重装后重新授权并关联 | 4GB 本地目录、SD 卡、共享存储 |
| 压缩包直读 | 不解压保存全部页面；可为 0 或只保留一个容器 | 容器必须仍可访问 | 容器在共享存储则仍在 | CBZ/ZIP 漫画库 |
| 完整导入 | 约等于去重后的原图总量 | 不受影响 | 需外部完整备份才能恢复 | 最重要、必须完全独立的漫画 |

另提供一个显式高级动作“移动进拾画阁资料库”：先复制到用户选择的共享目录，完成哈希验证后再请求删除源文件。默认不启用，任何源删除都必须二次确认。

### 10.3 原地挂载

流程：

```text
导入 → 挂载本地漫画目录
→ Android 系统目录选择器
→ 用户选择具体目录
→ App 保存持久 URI 权限
→ 流式扫描子目录与漫画压缩包
→ 用户确认分组映射
→ 建立本地索引，不复制原图
```

规则：

- 使用 Android `ACTION_OPEN_DOCUMENT_TREE` / Storage Access Framework。
- 只请求用户选定目录，不申请全盘权限。
- 默认只读，不改名、不移动、不删除源文件。
- 首次扫描、手动刷新和启动时轻量一致性检查分开。
- 文件位置变化后使用“相对路径 + 大小 + 修改时间 + 部分指纹”尝试重连。
- 授权失效或文件移动时标记“需要重新关联”，不能误判为漫画被删除。
- 重新选择同一目录后恢复漫画 ID、阅读进度、书签、分组和封面。
- 挂载只保存目录授权与索引；系统卸载 App 后授权不会被当作永久备份，重装仍需重新选择目录。

Android 官方文档确认：目录选择器只授予用户选择范围内的目录访问；持久 URI 权限可跨设备重启保留，但目标被移动或删除后仍会失效。

### 10.4 压缩包直读

CBZ/ZIP 不再默认解压为数百张永久文件：

```text
容器文件
├── 目录索引
├── ComicInfo.xml
└── 图片条目
     └── 打开当前页时按需读取 / 解码
```

支持策略：

| 格式 | v1.3 读取策略 | 永久解压全部图片 |
|---|---|---|
| CBZ / ZIP | 建目录索引，按条目读取；本地提供者可随机访问时优先零拷贝 | 否 |
| CBT / TAR | 建顺序索引，按当前阅读窗口解出临时页 | 否 |
| CBR / RAR | 视底层库和提供者能力；必要时把容器缓存到工作区 | 否 |
| CB7 / 7z | 固实压缩可能需要更大范围解压；使用受限临时缓存 | 否 |

对于不支持随机访问的 `content://` 提供者，App 必须先提示：

> 此来源不能直接定位压缩包内部页面，需要临时缓存整个压缩包。缓存可清理，原文件不会修改。

不能在后台悄悄复制 4GB 容器。

### 10.5 缓存预算

建议默认值：

```text
缩略图缓存：256 MiB
页面/压缩包工作缓存：512 MiB
预取范围：当前页前 1 页、后 2 页
空间低于 2 GiB：停止预取并提示
空间低于当前操作安全值：禁止开始整包缓存
```

- 用户可将页面缓存调整为 128 / 512 / 1024 / 2048 MiB。
- 使用 LRU 淘汰，正在阅读的页面和当前容器不可在使用中删除。
- 缩略图与页面缓存都属于可重建数据；原图和共享容器不属于缓存。
- 缓存清理不删除书架、阅读进度、书签、分组或源授权。
- Android 可能在空间不足时清理系统缓存，因此读取缓存前必须检查文件是否存在，不能把缓存当永久数据。

### 10.6 导入前容量预估

确认页必须同时显示：

```text
源文件大小：4.0 GB
保存方式：原地挂载
预计永久新增：约 180 MB（索引与缩略图上限内）
页面缓存上限：512 MB（可清理）
临时峰值：不复制整个 CBZ；若来源不支持随机访问将另行确认
```

完整导入则显示：

```text
预计永久新增：约 4.0 GB（重复内容会去重）
预计临时峰值：最大单个源文件 + 当前写入文件
卸载后恢复：需要外部 .mangabackup
```

### 10.7 无损原则

- 原地挂载和压缩包直读只读取原始字节，不重编码。
- 完整导入继续复制后做 SHA-256 校验。
- 缩略图可以使用有损 JPEG，因为它是可清理预览，不替代原图。
- 任何“节省空间”操作不得覆盖或重写用户的源文件。

## 11. 存储数据模型

schema 6 建议新增三类表，现有 `assets` 和 `comic_items` 保留：

同时给现有 `assets` 增加一个兼容字段，不重建旧表：

```sql
ALTER TABLE assets
ADD COLUMN storage_kind TEXT NOT NULL DEFAULT 'private_file';
```

- v1.2 资源全部自动得到 `private_file`，旧 `stored_path` 行为完全不变。
- 新的外部资源使用 `document_uri` 或 `archive_entry`；兼容用 `stored_path` 保持空字符串，读取代码必须先按 `storage_kind` 选择来源，不能再无条件拼接本地路径。
- 新来源首次建索引时以流式读取计算 SHA-256，不生成第二份永久文件；这会消耗一次扫描时间，但保留现有去重与完整性语义。

### 11.1 挂载根

```sql
CREATE TABLE mounted_roots (
  id TEXT PRIMARY KEY,
  display_name TEXT NOT NULL,
  root_uri TEXT NOT NULL,
  source_type TEXT NOT NULL,
  is_read_only INTEGER NOT NULL DEFAULT 1,
  last_scan_at TEXT,
  last_success_at TEXT,
  auth_state TEXT NOT NULL DEFAULT 'ready',
  fingerprint TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### 11.2 压缩包容器

```sql
CREATE TABLE archive_containers (
  id TEXT PRIMARY KEY,
  mounted_root_id TEXT,
  document_uri TEXT NOT NULL,
  display_name TEXT NOT NULL,
  archive_format TEXT NOT NULL,
  byte_size INTEGER,
  modified_at TEXT,
  content_fingerprint TEXT,
  access_mode TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'ready'
);
```

### 11.3 资源位置

```sql
CREATE TABLE asset_sources (
  id TEXT PRIMARY KEY,
  asset_id TEXT NOT NULL,
  source_kind TEXT NOT NULL,
  stored_path TEXT,
  document_uri TEXT,
  container_id TEXT,
  entry_path TEXT,
  byte_size INTEGER,
  modified_at TEXT,
  fingerprint TEXT,
  is_primary INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'ready'
);
```

`source_kind`：

- `private_file`：v1.2 现有私有原图。
- `document_uri`：SAF 原地文件。
- `archive_entry`：压缩包内部条目。
- `network_page`：现有网络书库按页缓存映射。

同一个逻辑资源可以拥有多个来源。例如一张图既有挂载来源，也被用户“固定离线”为私有副本。阅读时优先使用可访问、完整性更高的来源。

## 12. 备份、卸载与恢复

### 12.1 必须说清的事实

Android 官方行为是：卸载 App 会删除应用专属存储。因此不能承诺“什么都不做，卸载后私有原图仍在”。拾画阁提供三条可恢复路径：

1. 完整导入的数据：通过保存到共享目录或云盘的 `.mangabackup` 恢复。
2. 原地挂载的数据：原文件仍在共享目录，重装后重新授权并重连。
3. 压缩包直读的数据：共享目录中的 CBZ/ZIP 仍在，重装后重新授权并重建索引。

### 12.2 备份 manifest 4

新增：

- `shelfEntries`。
- `mountedRoots` 的非秘密描述和相对指纹。
- `archiveContainers` 与条目索引。
- `assetSources`。
- 缓存策略与存储模式。

不新增：

- SAF 授权本身。
- 网络密码、Token、Cookie。
- 可重建的页面缓存和缩略图缓存。

恢复时：

- 私有原图按原流程恢复。
- 挂载源显示“等待重新关联”。
- 用户重新选择目录后，通过指纹和相对路径批量匹配，不要求逐本重建。
- 未匹配项目保留在书架中并显示离线状态，不自动删除。

### 13.1 需要修改的可见项

- Android `android:label`：`私人书架` → `拾画阁`。

### 13.2 绝对不能修改

- SQLite 数据库文件位置和现有私有资源目录。

## 16. 验收标准

### 16.1 品牌与升级

- 桌面、最近任务、App 内和设置底部均显示“拾画阁”。
- 图标在圆形、圆角方形和主题图标下均不裁切。
- 包名和签名与 v1.2.0 一致，版本号为 `1.3.0+4` 或更高。
- 原位升级后漫画数、页面数、原图总字节和抽样哈希不变。

### 16.2 书架与分组

- 主书架始终三列。
- 每个分组卡都有完整外框和固定四格。
- 0～3 本时有真实空位，4 本以上显示前 4 个真实封面。
- 私密分组不泄露封面。
- 移动弹层显示四宫格、名称和数量。
- 漫画与分组可混合拖动排序，重启后顺序不变。
- 漫画拖入分组、移回根目录均可撤销。

### 16.3 返回与设置

- 在书单内侧滑返回只回主书架，不退出 App。
- 分组、私密区、设置和网络页返回路径符合状态表。
- 设置页不再常驻显示横跨卡片的大滑杆。
- 主书架滚动条不遮挡顶部按钮、三点菜单或底部导航。

### 16.4 4GB 存储

- 原地挂载模式不会向私有 `assets` 复制原图。
- CBZ/ZIP 直读模式不会永久解压保存全部页面。
- 缓存占用不超过用户设置上限的 10% 浮动。
- 来源不支持随机访问时，在复制整个容器前明确显示大小并请求确认。
- 清缓存后书架、阅读进度、书签和挂载关系仍在。
- 原图哈希不因阅读、建索引或生成缩略图而改变。

### 16.5 卸载恢复

- 外部 `.mangabackup` 在卸载后仍存在并可恢复私有数据。
- 共享目录/CBZ 在卸载后仍存在。
- 重装后重新选择挂载目录，可恢复原漫画 ID、分组、进度和书签。
- 网络凭据与 SAF 授权不伪装为已恢复；需要重新登录/授权时明确提示。

## 17. 风险与对策

| 风险 | 等级 | 对策 |
|---|---:|---|
| 改包名导致无法升级 | 极高 | 只改显示名，固定 `applicationId` |
| 新签名覆盖失败 | 极高 | 使用现有签名并先做 v1.2→v1.3 实机升级 |
| 混合排序破坏原顺序 | 高 | 新表增量迁移、事务草稿、pre-v6 快照 |
| SAF 授权被撤销 | 高 | 离线状态、重新选择、指纹重连，不删除条目 |
| 4GB 容器临时复制耗尽空间 | 高 | 能力探测、峰值预估、复制前确认、缓存硬上限 |
| RAR/7z 随机读取性能差 | 中高 | 容器缓存而非永久解压；先把 CBZ/ZIP 做稳 |
| 快速滚动与系统侧滑冲突 | 中 | 避让系统手势区、缩小视觉、扩大内部热区但不贴边 |
| 参考图形成拼贴感 | 中 | 只借鉴层级，沿用现有字体、蓝色与间距系统 |
| 图标来源或授权不清 | 中 | 使用参考图重建原创 Launcher 资产并保留来源说明 |

## 18. 最终建议

这次不要把拾画阁做成“缩小版微信读书”，而要把它做成一套更适合私人漫画资料的工具：

- 外观上：名称、图标和分组四宫格形成自己的识别度。
- 操作上：搜索、导入、选择、整理和返回都直接可见。
- 存储上：重要漫画可完整导入，大书库可原地挂载，CBZ/ZIP 可容器直读。
- 数据上：App 升级不动旧原图；卸载恢复依赖外部备份或仍存在的共享源，不给用户虚假承诺。

推荐优先顺序是：**先修返回与整理书架，再完成品牌/UI，最后做原地挂载与压缩包直读。** 这样每个 LOOP 都能独立验收并留下 Git 回退点，不会把最复杂的存储改造与所有 UI 变化一次性混在同一个不可回退版本中。
