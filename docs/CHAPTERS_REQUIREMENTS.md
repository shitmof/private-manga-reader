## 一、你的想法（我的转述）

你希望一本漫画不再是一条平铺的图片列表，而是**可编排的章节结构**，并在导入时就能决定怎么分：

1. **一本书可以有目录**：由若干章节组成，能看目录、能跳章节。
2. **导入时选模式**：
   - **分段导入** —— 一个内层压缩包 = 一个章节（7 个 cbz → 第 1 章到第 7 章）。
   - **整段导入** —— 全部内容作为一整章（183 张就是一章）。
3. **在整段的基础上还能再切**：比如 160 张，可以
   - 按固定张数自动分（每 8 张一章 → 20 章）；
   - 按你自己指定的范围分（自定义每章起止）；
   - 或者不切，160 张当一章看。

如果这三条我理解偏了，请直接指出哪一条。

## 二、当前代码的现状（已核对，非推测）

| 项 | 现状 | 结论 |
|---|---|---|
| `comics` 表 | 有 `id/title/cover_asset_id/folder_id/...` | 无章节字段 |
| `comic_items` 表 | 只有 `position`（全书唯一顺序） | **扁平，无章节归属** |
| 章节 / 卷 / 目录表 | **不存在** | 需新增 |
| 内层包导入 | 已支持（本轮修复） | 每个内层包被建为**独立的一本书** |
| 阅读器 | 单一连续列表 + 页码胶囊 | 无章节导航 |

**这意味着两件事：**

- 这是**数据模型变更**（要动数据库结构），不是纯界面改动。
- 当前行为与你的目标**不一致**：现在 7 个 cbz 会变成**书架上的 7 本书**，
  而你想要的是**1 本书里的 7 章**。

> ⚠️ 数据库结构变更必须配套升级与回退处理。当前代码**没有 `onDowngrade`**，
> 降级后再升级存在启动失败风险（此前排查已确认）。做章节功能必须同时补上，
> 否则会给已有数据的用户带来真实风险。

## 三、我建议的功能设计（供你挑选，不是最终方案）

### 3.1 数据层

新增“章节”概念，二选一：

- **方案 A：新增 `comic_chapters` 表**（推荐）
  字段：`id / comic_id / title / sort_index / start_position / page_count`
  `comic_items` 保持不变，章节通过**页码范围**映射。
  优点：改动最小，现有排序、编辑、导出逻辑基本不动。
  缺点：章节边界靠范围推导，插入/删除页时要重算。

- **方案 B：给 `comic_items` 加 `chapter_id`**
  优点：归属明确，插入删除更自然。
  缺点：要迁移全部历史数据，编辑页、导出、阅读器、备份都要跟着改。

### 3.2 导入流程（你关心的重点）

导入漫画压缩包时，在现有“确认导入”对话框上增加**分段方式**选择：

```
导入为新漫画

漫画名称   [________________]

分段方式
  ( ) 整段导入        全部内容作为一章
  ( ) 分段导入        每个压缩包作为一章         ← 内层包存在时才可选
  ( ) 自定义切分      按张数或指定范围分章

[当选择“自定义切分”时展开]
  方式  ( ) 每 [ 8 ] 张一章      ( ) 手动指定范围
  预计  20 章
  预览  第1章 1–8 · 第2章 9–16 · 第3章 17–24 …
```

要点：

- **只在有内层包时才显示“分段导入”**；单个 cbz 里只有图片时，
  这一项没有意义，不显示比显示成灰色更清楚。
- **默认值**要给一个明确选择，我倾向默认“分段导入”（有内层包时），
  因为你的原始诉求就是这个。
- **自定义切分要能预设章节名**：至少支持“第 N 章”自动编号，
  是否支持导入后改名见第八节。

### 3.3 阅读与目录

- 阅读器增加**章节目录**入口（顶部菜单里），列出章节名与页码范围，点击跳转。
- 阅读器底部页码胶囊的语义要明确：显示**全书页码**还是**本章页码**。
  我倾向“本章 3/16 · 全书 27/183”这种双段式，避免用户混淆。
- 上一章 / 下一章切换。

### 3.4 与现有功能的关系

| 现有功能 | 章节引入后的影响 |
|---|---|
| 图片编辑（排序/删除/移动） | 章节边界需随编辑重算；这是最容易出错的地方 |
| 导出 CBZ | 是否按章分文件？见第八节 |
| 书签 | 书签记全书位置即可，不需要改 |
| 阅读进度 | 记全书位置；目录里可显示“读到本章第几页” |
| 备份 / 恢复 | 章节信息必须进备份，否则恢复后目录丢失 |
| 私密书架 | 章节不改变私密语义，无需改 |

## 四、明确不做的事（避免范围失控）

- 不做多级目录（章下面再分节）。只做“一本漫画 → 若干章”这一层。
- 不改变现有扁平数据的行为，除章节外不动排序、归属、私密逻辑。
- 不为章节单独引入新的一级导航，仍从漫画详情页进入。
- 不把独立“书单”功能与章节合并（书单是跨漫画的集合，语义不同）。

## 五、风险与代价（我先说清楚）

1. **数据库迁移是硬成本**。要么加表（方案 A，风险低），要么改 `comic_items`（方案 B，风险高）。
   无论哪种，**都必须同时补上 `onDowngrade` 与迁移前自动备份**。
2. **图片编辑是最大的回归风险**。现有编辑页支持重排、批量移动、按范围选择，
   引入章节后每一次编辑都可能改变章节边界。这一块必须有针对性测试。
3. **备份格式要升版本**。旧备份导入时必须能兼容（按“整本一章”处理）。
4. **已有用户数据的处理**：现有漫画没有章节，迁移时统一视为“整本一章”，
   这样目录里只有一章，不破坏原有阅读体验。

```
7. 回归测试与真实设备验收
```

## 七、验收标准（我想按这个验，你看是否同意）

- 导入 7 个 cbz 的嵌套包，选“分段导入”后得到**1 本书、7 章**，章名可辨。
- 同样内容选“整段导入”，得到**1 本书、1 章、183 张**。
- 160 张选“每 8 张一章”，得到 20 章，且每章页码范围正确。
- 自定义切分能指定范围，边界与预览一致。
- 目录能跳章，页码显示不混淆。
- 旧数据（无章节）升级后不丢、不崩，显示为整本一章。
- 备份 → 恢复后章节结构完整。
- 编辑页删除/移动图片后，章节边界正确且不越界。
