# 私人漫画 / 插画阅读器 App
## 产品设计与开发交接原稿（Codex 版）

> 文档定位：这是给 Codex / 开发 Agent 直接执行的产品设计原稿。  
> 目标不是复刻 Pixiv，而是抽取其中“多图投稿 → 排序整理 → 连续阅读”这一核心体验，做成一个**完全本地、私有、无社交负担的手机漫画 / 插画书库**。  
> 当前阶段优先做出稳定、干净、可长期使用的 MVP，再逐步扩展。  
> 本文中的“必须 / 禁止 / 硬性规则”优先级最高。

---

# 0. 一句话定义

这是一个**私人本地漫画书库 App**：

用户从手机相册或文件系统导入大量图片，将它们整理成一本一本独立“漫画 / 图集”，在编辑模式中可自由排序，保存后以类似 Pixiv 多图作品的方式从上到下连续阅读。

核心链路：

```text
相册 / 文件
   ↓
导入 App 私有存储
   ↓
创建漫画 / 图集
   ↓
编辑排序
   ↓
保存
   ↓
沉浸式连续阅读
```

# 1. 产品目标

## 1.1 核心目标

只解决以下核心问题：

1. 一次导入大量图片。
2. 图片真正进入 App 私有存储。
3. 原系统相册删除后，App 内仍然可正常查看。
4. 不把图片重新写回系统相册。
5. 一本作品可以容纳大量图片。
6. 支持自动保留导入顺序。
7. 支持一键正序 / 倒序。
8. 支持单张图片自由拖动排序。
9. 支持保存后进入纯阅读状态。
10. 支持随时再次进入编辑状态修改。
11. 支持连续纵向阅读。
12. 图片之间保留很小、统一的间距。
13. 原图画质必须保持不变。
14. 不允许因为 App 处理造成原图体积膨胀。
15. 支持本地完整备份与恢复。
16. 整体 UI 必须非常干净、克制、安静。

# 4. 书库层

## 4.1 书库定义

书库是 App 启动后的主入口。

它包含多本独立漫画 / 图集，例如：

```text
书库
├── 漫画 A
├── 漫画 B
├── 漫画 C
├── 漫画 D
└── ...
```

## 4.2 漫画之间的排序

漫画本身支持手动排序。

交互：

```text
长按漫画卡片
→ 拖动
→ 调整其在书库中的位置
→ 保存当前书库顺序
```

不要强制只按创建时间排序。

可以提供辅助排序，但“自定义顺序”必须永远存在。

## 4.3 漫画卡片显示

每本漫画卡片最少显示：

- 封面
- 漫画名
- 图片数量
- 上次阅读位置（可弱化）
- 最近阅读时间（可选）

不要堆叠过多信息。

# 5. 单本漫画

## 5.1 单本上限

产品层限制：

```text
每本漫画最多 1000 张图片
```

注意：

> 1000 是产品限制，不应成为程序底层性能极限。

底层数据结构应允许未来把 1000 改成 2000、5000 等，而不需要重构核心架构。

# 6. 导入逻辑

## 6.1 图片来源

第一版支持：

- 系统相册
- 系统文件选择器

## 6.2 私有导入原则

图片被选择后：

```text
系统相册 / 文件
   ↓
复制原始文件
   ↓
App 私有目录
```

必须做到：

- 不依赖原相册路径长期显示
- 不只保存 URI 快捷引用
- 不因为相册原图删除而失效
- 不向系统相册写入新的副本

## 6.3 原相册保护

App **绝不自动删除系统相册中的源图**。

导入只是复制。

如果用户以后自行删除相册原图：

- App 内副本继续存在
- App 内阅读不受影响

---

# 7. 导入顺序

## 7.1 初始顺序

首次导入必须尽量保留用户选择图片时的顺序。

初始排列：

```text
用户选中顺序
→ App 中的初始顺序
```

不要擅自按照：

- 文件名
- 拍摄时间
- 修改时间
- EXIF
- 系统默认排序

重新洗牌。

## 7.2 正序 / 倒序

编辑模式提供全局：

```text
正序
倒序
```

建议行为：

- 点击“倒序”时，真实翻转当前图片顺序。
- 不要只保存一个隐藏的 `isReversed` 状态。
- 翻转后新的顺序就是当前真实顺序。

例如：

```text
1 2 3 4 5
↓ 倒序
5 4 3 2 1
```

这样后续手动拖动才不会产生逻辑混乱。

# 8. 图片编辑排序

## 8.1 编辑模式

阅读状态和编辑状态必须明确分离。

状态模型：

```text
阅读
  ↓ 点击编辑
编辑
  ↓ 保存
阅读
```

保存后并不是“发布到网络”，只是结束编辑。

## 8.2 单张拖动

每张图片必须可以：

```text
长按
→ 拖动
→ 插入任意目标位置
```

一次只拖动一张。

例如：

```text
1 2 3 4 5 6
↓
拖动第 5 张到第 2 位
↓
1 5 2 3 4 6
```

## 8.3 追加图片

已经存在的漫画必须允许继续追加图片。

默认：

```text
追加的新图片
→ 插入当前漫画末尾
```

之后用户可以手动拖动。

## 8.4 删除图片

默认安全规则：

```text
从漫画中删除图片
= 删除当前漫画中的“引用”
≠ 立即物理删除原图
```

如果一张原图被多个漫画引用：

- 从漫画 A 删除，不影响漫画 B。
- 只有当该原图不再被任何漫画引用时，才允许进入可清理状态。

建议加入：

- 回收站
- 彻底删除

彻底删除前应二次确认。

---

# 9. 重复图片处理

## 9.1 允许重复出现

产品层必须允许：

```text
同一张图片
→ 在同一本漫画出现多次
→ 在不同漫画中出现
```

用户想怎么看是用户自己的事情。

## 9.2 不重复物理存储

推荐使用内容哈希去重：

```text
原图字节
↓
SHA-256 / 等价内容哈希
↓
判断 App 私有图库中是否已存在相同文件
```

如果内容完全一致：

```text
只保存 1 份物理原图
多个位置保存引用
```

例如：

```text
PhysicalAsset IMG_A = 18MB

漫画 A：
1 → IMG_A
4 → IMG_A

漫画 B：
12 → IMG_A
```

物理空间仍只占约 18MB。

## 9.3 重复导入提示

导入时发现当前漫画中已经出现过相同图片：

提示：

```text
发现重复图片

[跳过重复]
[仍然导入]
```

不能擅自替用户删除。

# 10. 原图画质与文件完整性

这是硬性规则。

## 10.1 禁止处理原图

导入后的原始文件必须做到：

- 不重新压缩
- 不重编码
- 不降低 JPEG Quality
- 不放大
- 不缩小
- 不改变像素尺寸
- 不自动转 WebP
- 不自动转 AVIF
- 不自动转 JPEG
- 不重新保存 PNG
- 不裁切
- 不做 AI 增强
- 不做锐化
- 不做去噪
- 不做色彩调整

一句话：

> 导入时原始文件是什么字节内容，App 私有原图库就保存这份文件。

如实现允许，最好做到内容哈希校验前后完全一致。

## 10.2 不扩张原图内存 / 磁盘占用

禁止为了“高清化”产生一份比原图更大的永久版本。

可以额外生成缓存，但缓存必须：

- 与原图独立
- 可删除
- 可重新生成

---

# 11. 缩略图体系

编辑 1000 张图片时不能直接一次性解码 1000 张高清图。

因此需要：

```text
原图
→ 永久保存

缩略图
→ 编辑列表 / 书架封面使用
→ 可随时清理
→ 需要时重新生成
```

缩略图要求：

- 小尺寸
- 占用低
- 不影响原图
- 属于缓存
- 可批量清理

---

# 12. 阅读模式

这是整个 App 最核心的体验。

## 12.1 阅读形式

参考 Pixiv 多图作品的连续纵向阅读。

布局：

```text
图片 1
↓ 小间距
图片 2
↓ 小间距
图片 3
↓
...
```

## 12.2 手机端间距

图片之间不要出现大段空白。

目标：

- 有视觉分隔
- 但不破坏连续感
- 明显比桌面网页更紧凑

建议默认值：

```text
图片垂直间距：8dp ~ 16dp
```

最终数值可在实机中微调。

## 12.3 图片显示

默认：

- 按屏幕宽度适配
- 等比例缩放
- 不裁剪
- 不改变原图长宽比

## 12.4 横图

横图仍保持完整展示。

优先：

```text
fit width / contain
```

不强制裁成竖图。

可以允许点击 / 双击放大。

## 12.5 超长图

支持长图正常连续显示。

不要因为长图而截断。

## 12.6 沉浸阅读

阅读模式的 UI 应主动退出视觉中心。

默认尽量只看内容。

轻点屏幕：

```text
显示顶部工具栏
显示底部阅读信息
```

再次轻点：

```text
隐藏
```

必须记录每本漫画的阅读位置。

例如：

```text
漫画 A
总 638 张
上次阅读：第 417 张
```

默认回到上次阅读位置。

可提供：

```text

从头开始
```

不要每次强制从第一页打开。

# 14. 封面

默认：

```text
第一张图片 = 封面
```

但允许用户手动：

```text
设为封面
```

封面与第一页必须解耦。

例如：

```text
第 37 张
→ 设为封面
```

并不意味着第 37 张必须移动到第 1 位。

# 15. 导入可靠性

由于一次可能导入：

- 100 张
- 300 张
- 500 张
- 1000 张

因此不能使用“一张失败整批失败”的方式。

正确逻辑：

```text
逐项导入
↓
成功的保留
↓
失败的单独记录
↓
最后展示结果
```

例如：

```text
成功：987
失败：13

[重新导入失败项]
```

---

# 16. 存储空间检查

导入前建议预估：

```text
本次导入需要空间
当前设备可用空间
```

例如：

```text
预计导入：4.8 GB
当前可用：37.2 GB
```

如果空间不足：

必须在大量复制前明确提示。

# 28. 性能要求

## 28.1 书库

漫画数量增加时仍需流畅。

## 28.2 编辑 1000 图

不能一次性解码全部高清原图。

必须：

- 虚拟列表 / Lazy Grid
- 缩略图
- 按需加载

## 28.3 阅读 1000 图

必须：

- Lazy List
- 屏幕附近预加载
- 离屏释放大图解码缓存
- 原图文件本身不删除

## 28.4 内存保护

“原图不压缩” ≠ “一次把原图全部载入内存”。

磁盘原图保持不变。

显示时按屏幕需要进行解码缩放，是正常的运行时行为。

# 29. 图片显示与原图文件要区分

必须理解：

```text
磁盘中的原始文件
≠
屏幕上当前解码出来的 Bitmap / Texture
```

可以为了 UI 性能：

- 按目标显示尺寸解码
- 释放离屏 Bitmap
- 使用图片加载缓存

但：

> 绝不能覆盖或重新保存原文件。

---

# 30. 删除与垃圾回收

建议使用引用计数或引用查询。

逻辑：

```text
Asset
← ComicItem A
← ComicItem B
```

如果用户删除 ComicItem A：

```text
Asset 仍被 B 使用
→ 不删除 Asset
```

如果 Asset 已无任何引用：

```text
进入孤立资源
→ 可放入回收站 / 待清理区
```

只有：

```text
用户确认彻底删除
```

之后才真正删除物理文件。

# 31. 事务安全

以下操作需要考虑异常恢复：

- 创建漫画
- 批量导入
- 重排顺序
- 删除
- 备份
- 恢复

不要因为 App 崩溃造成整个漫画顺序损坏。

重要操作建议使用：

- 数据库事务
- 临时文件
- 完成后原子替换

# 35. Codex 实现约束

Codex 在实现过程中应遵循：

1. 不自行加入社交功能。
2. 不自行加入账号体系。
3. 不自行加入云服务。
4. 不压缩原图。
5. 不改写原图。
6. 不把原图重新写回系统相册。
7. 不为了“优化”降低画质。
8. 不把 1000 张图片一次性全部解码进内存。
9. 不将编辑态和阅读态混成一个复杂页面。
10. 不把 UI 做成重装饰。
11. 不擅自加入章节系统。
12. 不擅自改变已定义的信息架构。
13. 如果技术约束与产品硬规则冲突，优先停下来报告，而不是偷偷修改产品行为。

# 38. 最终产品气质

这不是：

> “一个功能很多的图库软件。”

而应该是：

> “一个只做私人漫画整理和阅读，但这件事情做得极其干净、稳定、可靠的工具。”

用户打开它以后不应该感觉自己进入了一个内容平台。

而应该感觉：

> “这是我的私人书架。”

最重要的体验顺序：

```text
内容 > 阅读 > 整理 > UI 装饰
```
