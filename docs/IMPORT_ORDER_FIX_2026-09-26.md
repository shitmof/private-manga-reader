## 已修复

### 1. 失败包重试后回到原位置

修复前：A、B、C 中 B 失败，实际重试后得到 A、C、B。

现在每个已完成批次记录实际入库图片的稳定条目 ID，重试保留最初的完整队列，按相邻已完成批次定位插入位置。排序通过现有数据库事务更新，不重新导入成功批次、不重写原图，不用图片哈希代替条目身份。

支持同一导入会话内多次失败、分次恢复和重复调用；“保留重复”策略下原本允许的重复页仍保留，已完成批次不会再次追加。会话状态只在内存中，本次未新增杀进程后自动续传能力。

### 2. 混合压缩包保持段落位置

修复前：先收集所有外层图片，再追加所有内层包，导致外层尾页被移动到书头。

现在按容器条目遍历，遇到内层包就结束当前连续散图段；散图段与内层包保留相对位置。每段内部继续使用有效 ComicInfo 页序或文件名自然排序。纯图片 CBZ 的既有排序规则不变。

明确例子：`A.cbz → 003.png → 002.png → C.cbz → tail.png`，导入为 `A → 002.png → 003.png → C → tail.png`。

### 3. 恢复 ComicInfo 标题优先

有效、非空的 `<Title>` 优先作为建议书名；空标题、无标题或损坏 XML 回退到文件名，图片仍可导入。

### 4. 修复重试替换封面

同一外层包的多个批次共用 sourceIndex，不能用它判断谁是原队列第一包。现在由导入服务识别原始首包，并按实际导入条目 ID 设置封面；中间包或末包重试不会替换原封面，首包恢复后也不会误选其他图片。
