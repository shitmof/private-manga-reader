# 私人书架：漫画文件、压缩包、网络书库与删除能力总体方案

> 文档状态：v1.1.0 已实现并通过 Android 验收
> 编写日期：2026-08-29  
> 当前稳定版本：`v1.1.0+2`
> 目标平台：Android APK 优先，保留 iOS 兼容设计

## 0. 实施结果

本方案原计划分阶段交付，实际在保持原 UI 风格和原地升级兼容的前提下完成了同一发布版整合：

- 数据库 v1→v3 增量迁移、迁移前快照、同签名覆盖安装与旧原图哈希保持已验证。
- 本地漫画软删除、回收站恢复、永久删除、页面多选删除与无引用原图清理已完成。
- CBZ/ZIP、CBR/RAR、CB7/7z、CBT/TAR 整包、多包队列、自然排序、`ComicInfo.xml`、加密包/越界路径/压缩炸弹保护已完成。
- 图片与压缩包均使用支持多选的系统选择接口；App 不设置单批 100 张限制，多批永远从当前末尾追加。
- WebDAV、OPDS/Komga/Kavita、SMB/NAS 只读挂载、本地索引、独立缓存、本地阅读记录、缓存清除与解除挂载已完成。
- 网络密码进入 Android 安全存储，不进入数据库或完整备份；跨来源下载不会转发书库凭据。
- 13 项自动化测试、真实 OPDS 设备链路、Android 15 Release 覆盖安装均通过。

实现后的总体难度仍评为 **中高（4/5）**。难点集中在压缩容器兼容、网络认证、缓存一致性和旧数据零损迁移；这些风险已通过回退标签、数据库快照、自动化测试和设备覆盖安装降低。

后文保留了最初的完整路线，便于以后继续迭代。没有列入用户本轮硬性范围、因此仍作为后续项的内容包括：Android“用私人书架打开”系统关联、远程散图文件夹逐页流式读取、单本网络漫画隐藏、书架来源筛选、SFTP、PDF 与 EPUB。当前远程漫画压缩包在首次阅读时先进入可清理缓存，再由本地解码器阅读；这是 WebDAV/SMB 无法普遍保证压缩包随机访问时的可靠回退方案。

## 1. 结论

四项要求可以组合进同一套产品架构，但不适合一次性堆进一个大版本。

整体难度属于 **中高（4/5）**，可以完成，主要困难不在 UI，而在以下部分：

1. 本地漫画、压缩包漫画和网络漫画必须共用同一套书架与阅读器。
2. 远程文件可能断网、改名、删除或发生版本变化。
3. 远程 CBZ/CBR 是整体压缩文件，不能保证所有网络存储都支持真正逐页随机读取。
4. 删除操作必须区分“删除书架记录、删除缓存、删除本地原图、删除网络挂载”，避免误删私人文件。
5. 压缩包必须防止目录穿越、压缩炸弹、损坏文件和异常占用存储空间。
6. 所有新版 APK 必须原地覆盖升级；已有漫画、原图、顺序、封面、阅读记录和备份不得被移动、重编码、清空或重新导入。

推荐采用“统一书源 + 本地索引 + 分层缓存 + 可恢复删除”的结构。最终用户看到的仍然是一个简单书架，技术差异隐藏在书源层内部。

## 2. 四项需求的统一定义

### 2.1 支持主流漫画文件

优先支持：

| 优先级 | 扩展名 | 实际容器 | 处理方式 |
|---|---|---|---|
| P0 | `.cbz`、`.zip` | ZIP | 第一阶段直接支持 |
| P1 | `.cbr`、`.rar` | RAR | 验证移动端解码库后支持 |
| P1 | `.cb7`、`.7z` | 7-Zip | 验证移动端解码库后支持 |
| P2 | `.cbt`、`.tar` | TAR | 使用量较低，但实现难度较低 |
| 独立能力 | `.pdf` | PDF | 需要专用渲染器，不能按图片压缩包处理 |
| 暂缓 | `.epub` | EPUB | 含 HTML、CSS 和目录规则，不当作普通 ZIP 处理 |
| 不建议 | `.cba` | ACE | 格式老旧，移动端可靠支持不足 |

CBZ 本质上是包含连续图片的 ZIP，因此 CBZ 与普通图片 ZIP 共用解析引擎。

### 2.2 ZIP / CBZ 在手机上自动解压并配置

用户可以从 App 文件选择器选择，也可以在系统文件管理器中使用“用私人书架打开”。

标准流程：

```text
选择 ZIP / CBZ
→ 校验真实文件格式
→ 安全扫描压缩目录
→ 识别图片、目录和 ComicInfo.xml
→ 生成名称、封面、页数和预计空间
→ 用户确认
→ 解压图片并进入现有 SHA-256 去重管线
→ 创建漫画
→ 清理临时文件
```

自动配置规则：

- 一个压缩包默认创建一本漫画。
- 有 `ComicInfo.xml` 时优先读取标题与封面信息。
- 无元数据时使用压缩包文件名作为漫画名。
- 默认按完整相对路径进行自然排序，例如 `1、2、10`。
- 自动忽略 `__MACOSX`、`.DS_Store`、`Thumbs.db`、TXT、XML 等非图片文件。
- 多层目录默认合并为一本。
- 存在多个顶级图片目录时，提供“合并为一本”与“按顶级目录分别建册”。
- 多选多个漫画文件时，每个文件创建一本漫画。
- 原图保持原始字节，不重新编码。
- 用户原始 ZIP / CBZ 不会被 App 删除或修改。

### 2.3 网络存储挂载与直接阅读

目标不是“从网盘下载再导入”，而是把远程目录作为长期书源挂载到 App：

```text
添加网络书库
→ 连接服务器
→ 选择漫画根目录
→ 建立本地索引
→ 网络漫画显示在书架
→ 阅读时按需获取页面
→ 阅读记录只写本地
```

网络协议优先级：

1. **WebDAV**：适合 Nextcloud、群晖、坚果云和多数个人服务器。
2. **OPDS / Komga / Kavita**：最适合漫画按页读取和服务器元数据。
3. **SMB / NAS**：适合家庭局域网共享文件夹。
4. **系统文件提供商**：Android SAF、iOS Files，以及接入系统的云盘客户端。
5. **SFTP**：作为后续高级入口。

网络书库默认只读。App 不上传、不改名、不移动、不删除远端文件。

### 2.4 完整删除能力

删除能力应分为五种不同语义：

1. 从一本漫画中删除某张图片。
2. 从书架删除整本本地漫画。
3. 彻底删除已经没有任何漫画引用的本地原图。
4. 从书架移除某本网络漫画并清理缓存。
5. 解除整个网络书库挂载。

这些操作不能共用一个含糊的“删除”按钮。

## 3. 当前删除能力核对

当前版本并非完全没有删除代码，但用户入口和恢复能力不完整：

- 漫画详情页右上角菜单已经有“删除漫画”。
- 编辑模式可以选中一张图片并删除该图片引用。
- 设置页可以彻底清理无引用原图。
- 相同原图被多本漫画引用时，删除一本中的引用不会破坏另一本。

当前不足：

- 书架首页没有明显的长按、批量选择或删除入口。
- 删除漫画入口隐藏在详情页溢出菜单中，发现性不足。
- 编辑器当前以单选为主，不能高效批量删除页面。
- 删除漫画后原图进入“待清理”，用户不容易理解两阶段删除。
- 没有回收站和撤销恢复。
- 没有网络漫画、网络缓存和网络挂载的删除语义。

因此下一版应把已有底层能力整理成完整的用户功能。

## 4. 推荐删除设计

### 4.1 本地漫画删除

书架长按漫画进入选择模式：

```text
长按漫画
→ 单选或多选
→ 删除
→ 移入回收站
```

第一步只执行软删除：

- 漫画从正常书架隐藏。
- 保留图片引用和阅读记录。
- 回收站内可以恢复。
- 默认保留 30 天，用户也可以手动永久删除。

永久删除时：

- 删除漫画记录和图片引用。
- 检查每个物理原图是否仍被其他漫画引用。
- 有其他引用时保留物理文件。
- 完全无引用时才允许删除原图和缩略图。

### 4.2 单张与批量页面删除

编辑模式改为支持多选：

```text
点选 / 长按图片
→ 选择多张
→ 从本漫画移除
→ 保存后生效
```

保存前可以撤销；取消编辑时不改变原漫画。

### 4.3 网络漫画删除

网络漫画不使用“删除远端文件”措辞，只提供：

- 从书架隐藏。
- 清除本地页面缓存。
- 取消离线保存。
- 移除本地索引。
- 保留或清除本地阅读记录。

默认永远不删除服务器上的 CBZ、图片或目录。

### 2.5 原地升级与旧数据零改动

升级必须满足以下硬性规则：

- Android `applicationId` 永久保持 `com.shitmof.private_manga_reader`。
- 新 APK 的 `versionCode` 只增加，不回退。
- 新 APK 必须继续使用与已安装版本兼容的签名证书。
- 已有 `assets/` 原图目录不移动、不改名、不重编码。
- 已有 `thumbnails/` 可以重建，但升级过程不主动清空。
- 现有 SQLite 表采用增量迁移，只新增表、索引或可空字段，不破坏旧表结构。
- 迁移在事务中执行；失败时保持旧数据库可用。
- 第一次启动新版时，迁移前创建数据库安全快照和资产清单。
- 迁移前后核对漫画数、图片引用数、物理资源数和原图总字节数。
- 新功能通过新的书源表和缓存表接入，现有本地漫画自动归类为 `local`，不重新导入。

当前 `v1.0.0` APK 经实际核验使用 Android Debug 证书签名，证书 SHA-256 为：

```text
3724690e26bae1597ad10221c10f2b2b15ade2a5bfdbaf408834dc46eaace1a5
```

因此下一个功能版本开始前必须先完成签名保护：安全保留当前签名材料，禁止上传到 GitHub，后续 APK 使用相同签名，或者在实机验证通过后采用正式的签名轮换方案。Android 要求应用 ID、签名证书和版本代码满足更新条件；否则只能卸载旧版，而卸载会清除 App 数据。

为了保留“向下回退”的能力，数据库迁移保持向后兼容；必要时提供一个使用相同签名、但 `versionCode` 更高的“回退 APK”。这个 APK 使用旧稳定功能代码读取原有本地表，让 Android 把它视为升级安装，而不是要求用户卸载。

### 2.6 多批图片与多压缩包连续追加

“一次最多选择 100 张”不能成为 App 的产品限制。

当前源码没有写死单次 100 张：文件选择器默认允许多选，App 当前明确限制是单本最多 1000 张。如果某台手机的系统相册选择器最多返回 100 张，这是系统 Photo Picker 或文件提供商的限制。解决方式是：

- 允许连续执行多次图片选择。
- 新一批图片永远追加在当前漫画末尾。
- 增加“选择文件夹”入口，绕过部分相册选择器的单批数量限制。
- ZIP / CBZ 只占一个选择项，包内图片不受“选择 100 个文件”的界面限制。
- App 自身不设置 100 张的单批上限，只受单本剩余容量和设备空间约束。
- 单本 1000 张继续作为可配置产品上限；如果未来决定提高，只修改统一配置，不重构存储结构。

在一本已经存在的漫画内导入压缩包时，执行严格追加：

```text
漫画原有页面
→ 压缩包 A 的全部页面
→ 压缩包 B 的全部页面
→ 压缩包 C 的全部页面
```

示例：

```text
原漫画：1～80
第一次导入 A.zip：A001～A120
第二次导入 B.cbz：B001～B090

最终顺序：
1～80 → A001～A120 → B001～B090
```

排序分为两层：

1. **压缩包之间的顺序**：按照导入队列中的顺序追加。若系统多选结果无法保证选择先后，确认页必须显示可拖动的压缩包队列，由用户确认后才开始导入。
2. **压缩包内部的作者顺序**：优先采用有效的页面元数据；没有页面元数据时，按完整相对路径进行数字感知的自然排序，并以压缩包条目顺序作为同名情况下的最终稳定顺序。

导入过程中不能让后完成解压的小压缩包抢到前面。即使并行扫描，也必须按队列逐包提交位置。每个压缩包完成后记录一个追加边界，失败重试时仍回到原队列位置。

书架首页导入多个压缩包时提供两种明确模式：

- 每个压缩包分别创建一本漫画。
- 合并为一本，并严格按照压缩包队列连续追加。

在漫画详情页或编辑页导入时，默认就是“追加到当前漫画”，不再询问是否另建一本。

### 4.4 解除网络挂载

解除挂载时明确列出影响：

- 删除该网络源的本地索引。
- 清除封面和正文缓存。
- 可选择保留阅读记录，方便以后重新挂载。
- 删除本机保存的认证凭据。
- 不触碰远端文件。

## 5. 统一书源架构

当前数据模型主要假定所有漫画图片都已经复制到本地。网络挂载加入后，需要把“书架中的漫画”与“漫画实际存放位置”分开。

推荐结构：

```text
LibraryBook（书架中的逻辑漫画）
├── LocalAssetsSource      本地图片
├── ImportedArchiveSource 解压导入的 CBZ / ZIP
├── WebDavSource          WebDAV 网络目录
├── OpdsSource            OPDS / Komga / Kavita
├── SmbSource             SMB / NAS
└── SystemDocumentSource  Android / iOS 系统文件提供商
```

统一接口至少包含：

```text
connect()
listBooks()
getBookMetadata()
listPages()
openPageStream()
getCover()
getVersionFingerprint()
```

书架、详情页和阅读器只依赖这个统一接口，不直接判断 WebDAV、SMB 或本地文件。

压缩格式也必须集中到一个统一适配层，禁止每增加一种格式就在 UI 和业务逻辑中复制一套代码：

```text
ArchiveAdapter
├── ZipArchiveAdapter     ZIP / CBZ
├── RarArchiveAdapter     RAR / CBR
├── SevenZipArchiveAdapter 7Z / CB7
└── TarArchiveAdapter     TAR / CBT
```

所有适配器提供相同能力：格式探测、读取条目、打开条目流、报告压缩与解压大小、识别加密和校验完整性。图片过滤、作者顺序、空间检查、哈希去重、追加位置和失败回滚只实现一次。

## 6. 数据模型调整

建议新增以下概念：

### 6.1 `sources`

保存书源定义：

- 类型：local、webdav、opds、smb、system-document。
- 显示名称。
- 服务器地址或目录标识。
- 连接状态。
- 最近扫描时间。
- 认证凭据的安全存储引用。

不在 SQLite 中直接保存密码。

### 6.2 `books`

逻辑漫画：

- 所属书源。
- 远端稳定 ID 或本地 ID。
- 名称、封面、页数。
- 阅读进度。
- 是否已删除。
- 是否离线保存。
- 远端版本指纹。

### 6.3 `pages`

页面定位：

- 本地页面指向已有 `asset_id`。
- 网络页面保存远端 locator，不要求永久本地文件。
- 已缓存时记录缓存文件和校验值。

### 6.4 `cache_entries`

管理：

- 封面缓存。
- 页面缓存。
- 整本远程压缩包缓存。
- 最近访问时间。
- 是否由用户固定离线保存。

## 7. 网络直接阅读流程

### 7.1 远端图片目录

```text
打开漫画
→ 获取页面清单
→ 请求当前页
→ 预取后面 2～3 页
→ 页面写入临时缓存
→ 本地保存阅读位置
```

这是最接近真正逐页读取的模式。

### 7.2 OPDS / Komga / Kavita

如果服务器提供页面流接口，App 可以按页请求，不需要下载整本压缩包。这是网络漫画的最佳体验。

### 7.3 WebDAV / SMB 上的 CBZ、CBR

远端压缩包需要分情况处理：

- 支持可靠随机读取或 HTTP Range：读取压缩目录并按需获取页面数据。
- 不支持 Range：自动把整本压缩包下载到受控缓存，然后从缓存阅读。
- 网络断开：已经缓存的页面继续可读，未缓存页面显示重新连接入口。

“直接阅读”指用户无需手动下载和导入，不代表手机完全不产生临时缓存。

## 8. 本地阅读记录

所有阅读状态默认只存在手机本地：

- 当前页码。
- 页内滚动位置。
- 最近阅读时间。
- 本地书架排序。
- 离线保存状态。
- 书签和收藏（未来能力）。

网络漫画的稳定身份建议使用：

- WebDAV：服务器 ID、远端路径和 ETag。
- OPDS / Komga / Kavita：服务器提供的 Book ID。
- Android SAF：稳定 Document ID。
- SMB：共享目录、相对路径、大小和修改时间组合。

远端文件改名或更新时，优先迁移原阅读记录；无法安全判断时保留旧记录并提示用户确认，不静默覆盖。

## 9. 缓存策略

建议提供三档：

| 模式 | 行为 |
|---|---|
| 仅封面 | 只缓存封面与书库索引，正文实时获取 |
| 智能缓存 | 默认，缓存最近漫画和阅读位置附近页面 |
| 离线保存 | 用户指定整本保存到本地 |

默认正文缓存上限建议为 2 GiB，可在设置中调整。

缓存采用 LRU 清理：

- 优先清理最久未访问的正文页面。
- 不自动删除用户固定的离线漫画。
- 不随缓存清理删除阅读记录。
- 封面和索引占用很小时单独保留。

## 10. 压缩包安全要求

ZIP / CBZ 导入不能直接调用“全部解压到目录”，必须逐项检查：

- 通过文件头识别真实格式，不只信任扩展名和 MIME。
- 拒绝 `../`、绝对路径和目录穿越。
- 不创建压缩包中的符号链接。
- 限制单张图片大小。
- 限制总解压体积。
- 限制异常压缩比，防止 ZIP Bomb。
- 不设置单批 100 张上限；保留当前单本 1000 张的可配置产品上限。
- 导入前检查可用空间。
- CRC、读取或图片校验失败时显示明确错误。
- 加密压缩包第一阶段明确提示暂不支持。
- 中断、取消和失败后清理所有临时文件。
- 第一阶段不递归解压压缩包中的压缩包。

建议默认限制：

- 单张解压后最大 200 MiB。
- 单批图片不限制为 100 张；单本默认最多 1000 张图片。
- 预计使用空间不得超过当前可用空间的 80%。
- 对异常压缩比进行拒绝或二次确认。

## 11. 网络安全要求

- 网络书源默认只读。
- WebDAV、OPDS 和服务器 API 优先使用 HTTPS。
- 不允许静默忽略证书错误。
- 局域网 HTTP 或自签证书必须由用户明确开启。
- 密码、令牌进入 Android Keystore / iOS Keychain。
- 密码不进入 SQLite、日志、GitHub 或备份文件。
- `.mangabackup` 可以保存书源地址与阅读记录，但不保存密码。
- 日志不得记录带认证信息的完整 URL。
- 解除挂载时删除本地凭据，绝不尝试删除远端漫画。

## 13. 分阶段实施方案

### 阶段 0：升级安全门

难度：中高，工程量 M，但必须最先完成。

- 冻结 `applicationId` 与当前签名身份。
- 安全保存签名材料，不进入 GitHub。
- 建立数据库迁移前快照与迁移后计数核对。
- 所有数据结构迁移只做增量、事务化修改。
- 在装有真实 `v1.0.0` 数据的 Android 设备上执行覆盖安装测试。
- 验证旧漫画、原图哈希、顺序、封面、进度和备份全部不变。
- 准备不卸载 App 的回退 APK 流程。

### 阶段 A：删除闭环与书源基础

难度：中等，工程量 M。

- 建立开发前回退标签。
- 增加书架长按和批量选择。
- 增加回收站和恢复。
- 增加批量页面删除。
- 明确引用删除、原图删除和缓存删除的区别。
- 建立统一 `BookSource` 接口和数据库迁移骨架。

### 阶段 B：CBZ / ZIP 漫画文件

难度：中等，工程量 M。

- App 内选择一个或多个 CBZ / ZIP。
- 支持系统“用私人书架打开”。
- 安全扫描、自然排序、元数据和封面识别。
- 支持可拖动的多压缩包导入队列。
- 支持多个压缩包按队列连续追加到当前漫画。
- 自动建册并进入现有哈希去重管线。
- 增加损坏包、ZIP Bomb、目录穿越和 1000 页边界测试。

### 阶段 C：WebDAV 网络挂载

难度：较高，工程量 L。

- 添加、测试和解除 WebDAV 书源。
- 只读取远端目录和漫画文件。
- 建立本地索引、封面缓存和阅读记录。
- 支持远端图片文件夹逐页阅读。
- 支持远端 CBZ 自动缓存后阅读。
- 支持断网、重连、超时和远端版本变化。

### 阶段 D：OPDS / Komga / Kavita

难度：中高，工程量 L。

- OPDS 目录浏览。
- 服务器漫画详情和封面。
- 页面流读取。
- 与本地阅读记录、缓存和书架排序结合。

### 阶段 E：CBR / CB7 / CBT 与 SMB

难度：高，工程量 XL。

- 验证 RAR 与 7-Zip 移动端解码实现、许可证和 APK 体积。
- 支持 CBR、CB7 和 CBT。
- 加入 SMB/NAS 书源。
- 验证大文件随机读取、弱网和不同 NAS 兼容性。

## 15. 验收标准

### 15.1 删除

- 书架可以单选和批量删除漫画。
- 删除后可以在回收站恢复。
- 永久删除不会破坏其他漫画引用的相同原图。
- 网络漫画删除不会触碰远端文件。
- 清理缓存不会清除阅读记录。

### 15.2 CBZ / ZIP

- 支持中文、日文和特殊字符文件名。
- `1、2、10` 自然排序正确。
- `ComicInfo.xml` 标题和封面读取正确。
- 1000 张可导入，第 1001 张被拦截。
- 损坏包、空包、加密包有明确提示。
- 目录穿越和 ZIP Bomb 测试被拦截。
- 导入后原图哈希与压缩包内图片一致。
- 用户原压缩包不被修改或删除。

### 15.3 网络书库

- 可以连接、测试、挂载和解除 WebDAV/OPDS 书源。
- 网络漫画可以和本地漫画同时显示。
- 阅读进度在杀进程、重启和断网后仍保留。
- 远端断开不会导致 App 崩溃。
- 已缓存页面断网可读。
- 远端变化可重新索引，不静默覆盖错误漫画。
- 凭据不出现在数据库、备份和日志中。

### 15.4 升级兼容

- 在已安装 `v1.0.0` 且已有真实漫画数据的设备上直接安装新版 APK 成功。
- 升级不要求卸载旧版本，不要求清空数据。
- 升级前后漫画数、页面引用数、原图文件数和原图总字节数一致。
- 升级前后抽样与全量自动化校验的原图 SHA-256 一致。
- 漫画名称、封面、顺序、阅读进度和设置保持不变。
- 数据库迁移失败时可以回到旧数据库快照。
- 回退 APK 可以在不卸载 App 的情况下安装，并继续读取原有本地漫画。

### 15.5 连续追加顺序

- 手动图片第二批从第一批末尾继续追加。
- 压缩包 B 的第一页永远位于压缩包 A 的最后一页之后。
- 三个以上压缩包按导入队列稳定排序。
- 解压速度不同不会改变最终顺序。
- 某一压缩包失败重试不会跑到队尾或插入错误位置。
- `ComicInfo.xml` 页面顺序有效时优先采用；否则使用自然文件名顺序。
- 系统选择器限制单次 100 张时，可以重复追加直到达到单本剩余容量。

## 16. 难度评估

| 模块 | 难度 | 原因 |
|---|---:|---|
| 删除入口与批量选择 | 2/5 | 已有删除仓储方法，主要补齐交互 |
| 回收站与安全物理删除 | 3/5 | 需要数据库迁移、引用计数和恢复逻辑 |
| CBZ / ZIP 导入 | 3/5 | 已有 ZIP 库和图片导入管线，重点是安全扫描 |
| 原地升级与签名保护 | 4/5 | 已发布 APK 使用 Debug 证书，必须保持签名与数据迁移兼容 |
| 多压缩包稳定连续追加 | 3/5 | 需要导入队列、位置预留和失败重试不乱序 |
| CBR / CB7 | 4/5 | 需要新的可靠解码方案和移动端兼容验证 |
| WebDAV 图片目录 | 4/5 | 涉及认证、索引、缓存、断网和版本变化 |
| 远程 CBZ 直接阅读 | 4.5/5 | 依赖 Range/随机读取，必须设计下载缓存回退 |
| OPDS / Komga / Kavita | 3.5/5 | 接口较清晰，但要统一认证、页面流和本地状态 |
| SMB / NAS | 4.5/5 | 协议、局域网、超时和设备兼容性复杂 |
| 四项完整组合 | 4/5 | 可控，但必须分阶段，不适合一次性上线 |

## 17. 最终判断

这套方案不是“改几个按钮”的小功能，但也不是不可控的重写。

当前项目已经具备 SQLite、内容哈希、私有原图、缩略图缓存、连续阅读、备份恢复和基础删除方法，这些可以继续复用。真正需要新建的是升级安全门、统一书源、统一压缩适配层、稳定导入队列、网络索引、远程缓存、回收站和多种删除语义。

最安全的路线是：先冻结签名并完成升级数据保护，再完成删除闭环与 CBZ/ZIP 连续追加，然后做 WebDAV，之后接 OPDS/Komga/Kavita，最后处理 CBR/CB7 和 SMB。这样每个阶段都有可安装 APK 和 Git 回退点，不会为了网络功能破坏现有本地阅读能力。
